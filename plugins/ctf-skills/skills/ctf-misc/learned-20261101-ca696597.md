# Kiosk 逃逸 + root 设备管理器组件覆盖提权

## 什么时候用

- 只给 VNC 口令，画面是全屏 kiosk（QtWebEngine/浏览器壳指向本机 Web 应用），目标是读 root 才可读的文件。
- 底层桌面（XFCE 等）仍在运行，启动脚本只禁用了部分快捷键（Super、Alt+F2、Ctrl+Alt+T 之类），还有漏网的。
- `ps -eo user,pid,ppid,cmd --forest` 里有 root 常驻设备管理进程；`busctl list --system` 能看到厂商 D-Bus 名，方法含 GetStatus/ListComponents/ReloadComponents。
- 组件目录存在 user 覆盖目录且属主是低权用户；`/run/<厂商>` 下的状态文件对该用户可写。
- 签名实现带 `include_sha256=False`，只签 `id|type|entry|name|version|vendor`，不覆盖入口文件内容。

## 怎么做

1. VNC 交互：先读 12 字节确认裸 RFB（`RFB 003.008\n`），用 `vncdo -s host::port -p pass ...` 驱动。先试 `key ctrl-alt-f`（或 Super/Ctrl+Alt+T 变体）打开被禁列表之外的桌面快捷键。
2. 窗口可能开在 kiosk 后面：在同一次 vncdo 调用里 `key alt-tab` → 截图确认 → 再点击。Thunar 按 `Ctrl+L` 聚焦位置栏（`Ctrl+A` 是“全选文件”不是选文字），输入 `/usr/bin/xfce4-terminal` 回车，直接得到 shell。
3. 侦察：`ss -ltnp`、`ps -eo user,pid,ppid,cmd --forest`、`busctl list --system`、`ls -ld /run/<厂商> /var/lib/<厂商>/components/user`。
4. 读 loader 与 signature 源码，确认三件事：签名覆盖哪些字段、用户目录如何扫描（`iterdir()` 后按 manifest id 归类）、状态文件判据（常见 `read_text().strip() == "disabled"`）。
5. 复制 vendor 的合法 `manifest.json` 到 user 覆盖目录（保持签名有效），写入同名 entry 的恶意 `.py`：`on_load()` 里把 `/root/flag.txt` 拷到低权用户可读路径并 `chmod 644`。
6. `echo disabled > /run/<厂商>/<组件>.status`（目录/文件可能不存在，先 `ls -ld`）。
7. `dbus-send --system --print-reply --dest=<bus> <object> <interface>.ReloadComponents`；返回 JSON 里出现 `"source":"user-override"` 与 `"<组件>_disabled":true` 即覆盖生效，root 执行了 `on_load`。
8. 读取侧信道文件。

## 坑

- 新开 vncdo 会话会重置窗口层叠，点击落到 kiosk 页面上（`Ctrl+A` 变成选中网页文本，`type` 进不了地址栏）。必须在同一会话内先 alt-tab 再操作，或每次点击前重新截图确认。
- 长命令的 `type` 后紧跟的 `key enter` 可能不执行：命令停在提示符。把 `key enter` 拆成独立一次调用再发。
- 状态文件/目录可能不存在；侧信道文件必须 `chmod 644`，否则低权用户读不了。
- 别把签名缺口误读成“改 manifest 也能过”：签名覆盖元数据，改 id/version 会失败；能改的是 entry 指向的代码文件。

## 边界

- 前提是已拿到低权本地 shell；root 守护进程必须允许任意本地用户调用 ReloadComponents（default allow 政策）。
- loader 必须在该状态下选择用户覆盖目录；只对“已验证失败组件”开放覆盖的实现无法触发。
- 仅在 CTF/授权靶场使用。该题实例的 flag 是动态的，旧 writeup 的值不可复用。
