# 抓包重建 VNC/RDP 访问链与窃取数据（RFB 帧缓冲 + RDPDR + Restic）

## 什么时候用

- 给管理侧 + 内网两份 pcap 和 SSLKEYLOGFILE（`browser.keys`），题面要求重建登录链路、追踪文件传输、给出数据内容/哈希。
- 流量里出现 PVE/Proxmox 的 `/api2/json/nodes/<node>/qemu/<vmid>/vncwebsocket`，或 3389 的 RDP 会话。
- 问题形态：`node|vmid`、`宽|高|RGB888的sha256`、`ip:port|域\用户`、`仓库口令|校验哈希`、按键序列、`db文件名|大小|sha256`。
- 产物是 Restic 仓库、嵌套加密 vault、SQLite 数据库。

## 怎么做

1. TLS 解密：`tshark -r cap -o tls.keylog_file:browser.keys`；用 `http.request.uri contains "vncwebsocket"` 找到 WS 的 `tcp.stream`。
2. 重组 WebSocket：剥掉握手与 WS 帧头，client/server 两个方向分开；拼 RFB 3.8 的 `ServerInit` 与 `FramebufferUpdate`；解 Tight 编码；按矩形顺序合成 RGB888 帧缓冲。
3. 屏幕哈希：对合成后的原始 RGB888 字节做 SHA-256（不是 PNG 文件哈希）；普通矩形里带的指针像素要保留，不要另叠独立光标；宽高取自 `ServerInit`。
4. RDP 身份：X.224 连接请求里的 `mstshash=<账户>`，服务端证书 CN 是主机名 → `host:port|DOMAIN\user`。
5. RDPDR：在磁盘重定向通道（常见 MCS 1004）解析 RDPDR 头（Component/PacketId/Type/Length，小端）；用 CompletionId 把 Create 请求与返回的 FileId 关联；Write 按 FileId + Offset + Length 落盘。Restic 文件名等于内容 sha256，可逐文件验证重组是否正确。
6. Restic：用恢复出的口令解 `keys/`，`restic snapshots` 按解密后的时间选最新快照（注意时区），再 `restore`/`cat` 取文件。
7. UI 遥测口令：记事本正文单击=点、拖标题栏=划，只统计真正绘制的点击（仅激活窗口的单击不算），按桌面区域分组解摩尔斯；数字键盘每次交互后换位时，把鼠标事件与当时的画面帧对齐，剔除取消的拖动、处理退格、保留前导零。
8. 嵌套 vault：读 .NET IL 得文件格式（常见 PBKDF2-HMAC-SHA256 200000 次 → 64 字节；前 32 字节 AES-CBC、后 32 字节 HMAC-SHA256）；验签→解密→去填充→取出内层文件名与内容。
9. 核验：`sqlite3 "PRAGMA integrity_check;"` 与各表计数；最终答案按 `文件名|大小|sha256`。
10. 容器提交：`GET /` 拿 session cookie，解析 `<meta name="csrf-token">`；`POST /api/submit/<n>`（头 X-CSRF-Token + JSON body）；六问通过后 `GET /api/reward`。

## 坑

- 对 PNG 求哈希必错：压缩与元数据会变；必须对 RGB888 原始字节求。
- WS 负载不按方向分离、帧头没剥干净 → RFB 解析错位。
- RDPDR 按到达顺序猜句柄会错；必须用 CompletionId 关联，Write 偏移可能乱序。
- 快照按文件名排序会选错，要按解密后的时间（注意 UTC+8）。
- 摩尔斯/小键盘恢复要剔除“仅激活窗口”的点击和取消的拖动，前导零不能丢（如 12 位码的前两位 0）。
- reward flag 按容器/会话动态签发，writeup 里的 flag 不可复用；Windows 下 JSON body 用 `curl --data-binary @file`，内联参数可能被吞导致服务端回“请输入答案”。
- 提交有解锁依赖（第 3 问通过后才给第二个密钥文件）。

## 边界

- keylog 必须覆盖目标 TLS 会话；RDP 磁盘重定向必须启用，否则没有 RDPDR 磁盘通道。
- Tight/JPEG 解码需要真实解码器；附件若是不同 take（大小/哈希不同）必须重新推导全部答案。
- 仅在 CTF/授权环境中分析涉案流量。
