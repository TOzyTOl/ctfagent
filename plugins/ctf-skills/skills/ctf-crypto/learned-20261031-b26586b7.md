# 小指数 RSA + 共享因子分解 + 对称密钥复用 —— 可复用笔记

## 什么时候用

附件是「出题脚本 + 输出文件」的组合，输出里有 `N = ...` / `c = ...` / `iv = b'...'` / `ciphertext = <hex>` 这样的四行，并且脚本里出现下面任一特征：

- `e` 很小（3、5、17）且 `c = pow(key, e, N)`，但 `c` 的位长约等于 `N` 的位长（本类题 N 2048 位、c 2047 位）。这说明消息不是小值，不能指望直接开根。
- 同一个整数 `key` 既进了 RSA，又被 `long_to_bytes(key)[:16]` 之类的方式截断当对称密钥用。于是「求出 key」= 「拿到 AES 密钥」，没有别的路。
- 输出文件的 `iv` 是 **Python bytes 字面量**（`b'\x91\x16...'`），`ciphertext` 是 hex 字符串；`ciphertext` 长度只有几十字节、是 16 的倍数 —— 明文很短，一次 CBC 解密就能定案。

命中这些特征时，第一件事不是开三次方，而是算 `gcd(c, N)`。

## 怎么做

**0) 先给自己造已知答案样例，校准工具链。** 这是本次运行里明确验证过的做法：在 `solve.py` 里写 `--selftest`，用随机 1024 位素数自造 N 和 key，分别覆盖「gcd 非平凡」「精确立方」「c+kN 命中」三条候选路径，每条都断言能还原预设明文。**检测器的「没找到」只有在它先在正例上 P(A|正例)=1 时才有意义。** 自测全 PASS 再碰真实附件，否则阴性结论不可信。

**1) 解析附件，不要 `eval` 整行。** 完整精简实现见 `work/solve_min.py`（约 90 行，可直接 `python -I -X utf8 solve_min.py <output.txt>` 复用）。

```python
import ast
vals = {}
for line in open(path, encoding="utf-8").read().splitlines():
    if "=" in line:
        k, v = line.split("=", 1); vals[k.strip()] = v.strip()
N = int(vals["N"]); c = int(vals["c"])
iv = ast.literal_eval(vals["iv"])          # bytes 字面量，安全求值
ct = bytes.fromhex(vals["ciphertext"])
```

**2) 用 gcd 直接分解 N。**

```python
from math import gcd
p = gcd(c, N)
if p in (1, N):
    raise SystemExit("gcd 平凡，此路不通，换别的攻击面")
q = N // p
```
p 是否为素数、p、q 是否不相等，用 40 轮 Miller-Rabin 自证（不必装 sympy），并断言 `p*q == N`。

**3) 在 mod q 上开三次方。** `q % 3 != 1` 时 `d = pow(3, -1, q-1)` 存在，`kq = pow(c, d, q)`，并回验 `pow(kq, 3, q) == c % q`。

**4) 在 mod p 上：** gcd 路径下 `c % p == 0`，故 `key^3 ≡ 0 (mod p)` ⇒ `key ≡ 0 (mod p)`。

**5) CRT 合并** `x ≡ 0 (mod p)`、`x ≡ kq (mod q)`，得 `x = key mod N`。**必须回验 `pow(x, 3, N) == c`**，不成立就是前面某步错了。

**6) 处理 t 的不确定性。** CRT 只给出 `key mod N`。如果出题人写的是 `c = pow(key, 3, N)` 且 key 未归约，那么 `key = x + t*N`，t=0,1,2… 逐个试：`long_to_bytes(x + t*N)[:16]` 作 AES-CBC 密钥，密文解出来 padding 正确且符合 flag 格式的那个 t 才是真 key。**先验 pow(x,3,N)==c 只锁定 x，锁定不了 key。**

**7) 解密并做往返校验。** 用恢复的 key 重新加密明文，逐字节比对附件密文；不一致说明 key 或 iv 取错。独立复核（另写一个不 import 主解的脚本）能有效排除「照着错误逻辑复现出同样错误结果」。

## 坑

- **不要因为 e 小就先走「精确立方根」。** 实测：`gmpy2.iroot(c, 3)` 不精确，`c + k*N` 在 k≤1000 内也无解 —— 这个负结论只有在第 0 步 selftest 里正例能命中之后才可信，否则你分不清是「真没有」还是「检测器写错」。
- **不要假定 t=0。** selftest 路径 C 里真 key 取的是 `x + 3N`，而 `x` 本身完全满足 `pow(x,3,N)==c`，用它去解密得到的是错的明文。本次真实数据恰好 t=0，但那是事实不是先验。
- **不要 `eval` 输出文件的 iv 行**，用 `ast.literal_eval`；Windows 中文环境下加 `python -X utf8`，否则写文件/打印可能编码报错。

## 边界

- 需要 `gcd(c, N)` 非平凡，即 key 与 p（或 q）不互素。随机场景概率极低，这通常是出题人构造的弱点；gcd 平凡时整个方法不适用，得换攻击面。
- 需要 `q % 3 != 1`（e=3）才有唯一三次根；`q ≡ 1 (mod 3)` 时需模素数三次剩余求解，本次未实现、未验证。
- t 的枚举上界没有数学保证，只能靠「解出合法 padding + flag 格式」判停。已验证的情况只有：selftest 里人工构造的 t=3 能被找到，真实数据 t=0；上限取 64 在这两例上够用，更大的 t 未验证。
- 依赖本地 Python + pycryptodome；gmpy2 可选（脚本里留了纯整数二分回退，selftest 的 icbrt 校准覆盖过）。1024 位素数的确认只用 Miller-Rabin 概率判定，非确定性证明。
