# ArkTS / .abc 字节码 VM：解释器不校验 slot → ldlexvar 越界读写 → JSNativePointer 析构 ROP

## 什么时候用

- 附件是 `ark_js_vm`（官方 samples 的样例宿主）+ `libark_jsruntime.so`（OpenHarmony/ArkTS 运行时），
  服务收一个 `.abc` 并执行；`strings` 里能看见 `panda`、`ExecuteFromFile`。
- 运行时把 `.abc` 当**随应用签名的可信输入**：解释器不校验字节码，`ldlexvar`/`stlexvar`
  的 slot 是直接读出的立即数，`GetProperties(idx)` 只做 `idx + RESERVED_ENV_LENGTH`，
  release 下 `ASSERT` 被裁掉 → 以 env 为基址、向前最多 512KB 的堆越界读/写。
- 目标是拿 shell/读 flag，而 JS 侧没有可用的文件/命令 API。

## 怎么做

**1. 先把 abc 版本钉死，再谈利用**

`es2abc` 来自对应版本的 OpenHarmony SDK。整包 3 GB+ 时不必全下：tar 里只需要
`ohos-sdk/linux/ets-linux-x64-*.zip`（几十 MB），`es2abc` 在
`ets/build-tools/ets-loader/bin/ark/build/bin/`。编译一个 hello-world 后看 header：
`PANDA\0\0\0` + checksum，偏移 0x0C 起四个字节是版本（如 `18 00 00 00` = 24.0.0.0）。
**版本对不上就先停**，换 SDK 或确认版本字段；版本不对时解释器连第一条指令都走不到。

**2. 本地一定要能复现**

用附件自带的 `ld-linux` + `libc.so.6` 起 VM；宿主缺的 `libstdc++/libm` 从 ubuntu:24.04
容器补。命令形如：

```
./ld-linux-x86-64.so.2 --library-path .:/usr/lib/x86_64-linux-gnu ./ark_js_vm /w/x.abc
```

先放一个本地假 flag 验证整条链，再打远端；否则远端只有一句 `Segmentation fault`，
分不清是"链没跑"还是"跑了但没找到 flag"。

**3. 造探针：直接改 CodeData 里的指令流**

模板 JS 让 `outer()` 里的闭包捕获局部变量，强制生成 LexicalEnv；再把几个探针闭包的
字节码换成需要的指令（8 位形式）：

```
ldlexvar level,slot = 8a <level> <slot>
stlexvar level,slot = 8b <level> <slot>
lda v8 = 60 <v>   sta v8 = 61 <v>   return = 64
```

不要在源码层推算偏移：用 es2abc 编译后按字节模式定位（如 probe 的 `3c 00 61 00`
命中数；p3 的 `62 01 00 00 00 61 00 62 02`）。**命中数不够就停**，说明编译器版本变了，
生成规则不是同一套，硬跑只会崩在不可预测的位置。

**4. 任意读写：伪造 JSNativePointer，而不是改对象字段**

- 先用 `addrof` 探针（`lda v4; stlexvar`）把对象指针写进 scratch；
- 在 `scr`（堆内 ByteArray，数据内联）里伪造一个 JSNativePointer，`+8` 放目标地址；
- 把 `ArrayBuffer.data` 改成指向伪 NP；已经建好的 `Uint8Array` 每次访问都会走
  `NP->GetExternalPointer() + index`，于是变成任意地址 8 位读写器。
- **此后所有改址只写 fakeNP.externalPointer（scr[8..15]）**，绝不能再动 `ab.data`，
  否则下一条写就自毁。

**5. 泄漏顺序：libark → GOT → libc**

`addrof(vic)` → 读 `vic+32` 得它的 NP → NP 的 `deleter` 是
`NativeAreaAllocator::FreeBufferFunc`，减 libark 偏移得基址；
libark 开了 `BIND_NOW`，GOT 里 `execv`/`free` 的 JUMP_SLOT 已解析，读一个减去 libc 偏移。
**拿到报告/写up的偏移后，先用 `readelf -Wr` 查 JUMP_SLOT、用 `xxd` 核 gadget 字节**，
全对上再投入（这一步只要几分钟，能挡掉整份不可信的写up）。

**6. 控制流：VM 析构的 deleter 比主动 GC 稳**

把 ROP 链放在 victim NP 的 malloc 缓冲（地址已知、GC 不搬动），覆盖 NP：
`deleter = mov rsp,rdx; ret`，`data = 链地址`。程序正常结束 → `~EcmaVM` →
`ClearNativePointerList()` 对每个 NP 无条件 `Destroy()` → `deleter(env, ptr, data)`，
此时 `rdx = data`，栈迁移成功。

## 坑

- **宿主不注册 `console`/`print`/`assert_equal`**：默认 entry 下直接 `ReferenceError`。
  没有打印通道，诊断只能把命令塞进 ROP 的 `system()`（先 `id;ls /` 验证链是否执行），
  或写文件/侧信道。
- **别信通配路径**：`cat /home/*/flag*` 在 `drwxr-x--x`（可穿越、不可列目录）上展开失败，
  现象就是"链明明执行了却没有输出"。先 `cat /init.sh` / `env` 找确切 `FLAG_PATH`，
  再用固定路径读。
- **`ab.data` 不能逐字节回改**：u8 的指针就是 `ab.data` 的值，改第一个字节后下一条写
  就指向别处；拿完任意读写就放弃 ab/u8，把 ROP 放到独立缓冲。
- **主动 `ArkTools.gc()` 触发的 deleter 可能因为当前栈帧里的残留引用而不死**；
  VM 析构路径才是无条件的。
- **8 位 slot 只有 0..255**；wide 前缀（`fd 0c/0d`）可到 65535，但补丁更长、更容易写错。
- 堆布局常量（哪个 slot 落到哪个对象）与**模板 + 编译器版本**强绑定；换 SDK 必须重测，
  不要跨版本复用。
- 探针改完代码后，源码里的 `console.log` 之类调试语句会改变堆分配；调试版与最终版要分开构建。

## 边界

- 依赖 abc 未签名/未校验、解释器（`--asm-interpreter`）启用、无 seccomp/沙箱；
  有字节码校验或 JIT-only 的宿主不适用。
- 依赖 LexicalEnv 的 OOB 窗口可达目标对象；若环境分配顺序改变，需要重新标定 slot。
- 依赖 `JSNativePointer` 析构回调与 libark 的符号偏移；换运行时版本要重新定位。
- 依赖 libc 版本的 gadget/system 偏移；本地复现必须用附件自带 libc，或明确核对版本。
