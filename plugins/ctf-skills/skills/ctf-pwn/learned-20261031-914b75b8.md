# 关掉输出 + seccomp 白名单只留 read：用「表下标分派」把 flag 字节变成布尔判据

## 什么时候用

- 拿到 `host:port`，连上去只有一行提示，之后**再无任何输出**；`strings` 里能看到 `close`、`seccomp_init`、`open`，以及一个明显的 `flag` 文件名。
- 反汇编 `setup_sandbox` 里出现 `seccomp_init(<imm>)`：**先看这个立即数**。`0x00050000|errno` 是 `SCMP_ACT_ERRNO`（默认动作只返回错误），`0x80000000` 才是 `KILL_PROCESS`。前者意味着 ROP 照样能跑，只是 `write` 会 `EPERM` —— 题目就从"没法利用"变成"盲利用"。
- 程序在 `main` 开头就把 flag `open` 了，fd 留在 3：`read(3, ...)` 可以直接用，不需要 `open/openat`。
- 已经拿到栈溢出、能控 `rdi/rsi/rdx`（`ret2csu` 或 `pop` 链），但**能用的 syscall 只剩 `read`**。

## 怎么做

**1. 先把"输入函数"的行为钉死，别猜**

`objdump` 看清它是"一次 `read(n)`"还是"逐字节读到 `\n`"。逐字节版本有三条硬约束：发多少读多少（**时序决定阶段边界**）、`\n` 硬截断、`read != 1` 可能直接 `exit`。

```asm
mov edx, 1 ; lea rsi,[rbp-0xd] ; mov edi,0 ; call read
cmp rax, 1 ; jne exit
cmp al, 0xa ; je done        ; 换行截断
```

**2. 泄露与溢出共用一个 size 时，取"刚好覆盖返回地址"的值**

缓冲区 88 字节、canary 在 `rbp-8`：`size=136` 时，第一次只发 89 字节 + `\n`（printf 打到 canary 的 0 字节为止，泄 canary 尾 + saved rbp），第二次发满 136 字节正好覆盖 `canary/rbp/ret`。用 89 只能泄，用 136 才能两者兼得。

**3. 返回点选在"调用输入函数的那条指令"，用伪 rbp 做栈迁移**

`ret` 回到 `main` 里 `mov edx,[rbp-0x64]; lea rax,[rbp-0x60]; call get_input` 这一串，配合伪造 `saved rbp = BSS`，就能让程序**把下一段 payload 读进 BSS**，再由 `main` 的 `leave; ret` 把栈迁过去。

必须用 gdb 实测两件事，不能推：

```gdb
break get_input
commands
silent
printf "get_input dst=%p size=%d\n", $rdi, $rsi
continue
end
```

- `dst` 是否落在 BSS（`FAKE-0x60`）；
- `size` 是不是个**大的非零数**（它来自 `*(u32*)(FAKE-0x64)`，往往是 BSS 里的残留/现成大数）。为 0 就什么都读不进去，整条链静默失效；而因为它遇 `\n` 就停，只要 ≥ 你这一段长度即可。

顺带：`main` 的 canary 校验会落在 `FAKE-8`，在这一偏移把真 canary 放回去就过了。重入点通常会**执行两次**输入调用，溢出后要**补一行**打发掉第二次，否则永久阻塞（现象是"连接不关也不崩"，极易误判为成功）。

**4. 只读环境下的"输出"：自己造一个布尔通道**

关键在于找一条"以读到的数据为下标"的间接调用。`__libc_csu_init` 的调用 gadget 天然就是：

```
mov rdx, r15 ; mov rsi, r14 ; mov edi, r13d
call qword [r12 + rbx*8]
add rbx,1 ; cmp rbp,rbx ; jne ...
```

把 `read(3, S, 1)` 的目标 `S` 放在 epilogue 会 `pop rbx` 的那个槽上，后面的 `call [TABLE + S*8]` 就**以 flag 字节为下标**：

- `TABLE[b] = leave;ret` 且 `rbp` 指向自引用帧 → 命中时进程**自旋不死**；
- `TABLE[b] = 0` → `call 0` → **立刻 SIGSEGV**。

**表内容是我们自己 `read` 进去的，所以不要求连续**：可以只标记任意子集，探测就变成"字节是否属于集合 S"的成员测试，比"是否落在区间"灵活得多（按 UUID 字符集只有 17 个候选，5 次就能定位一个字节）。

**5. 远端判据要和包装器对齐，别信"半关闭"**

远程常常是 `wrapper`（fork + exec，管道 <-> TCP 转发，`poll` 驱动，写管道带超时）。**客户端 `shutdown(SHUT_WR)` 拿 EOF 判活，在接入层存在时经常不成立**。可用判据是：

| 子进程状态 | 灌 1MB 级数据时 | 判定 |
|---|---|---|
| 崩溃 | wrapper 写管道 `EPIPE` → 退出 → 连接 `RST`，`send` 抛异常 | 不命中 |
| 自旋 | 管道填满，`send` 阻塞但**不报错** | 命中 |

灌数据还会把管道灌满，等 wrapper 自己的写超时（常见 60 s）把子进程 `SIGTERM`，**自带清理**。

**6. 并行 + 单值复核**

如果每次探测都是"新连接 → 从文件头 `discard k` 字节 → 读第 k 个字节"，那么**位置之间零依赖**，可以并行（并发控制在 5 路内，否则自旋子进程会把容器会话打满，表现为新连接连 banner 都拿不到）。二分搜索怕假阴性，每个解出的字节再用 `{该字节}` 单探一次——**True 即证明**；位置越界时必然 False，天然识别结尾。

## 坑

- **`build(base, canary, k, lo, hi)` 这类"位置参数多"的构造器，`k` 传错会伪装成"利用失败"**：所有位置都读到第 0 个字节，输出全是同一个字符（正好是二分在候选集末尾的收敛值）。用 strace 看 `read(3, ...)` 的**长度**，一眼就能确诊。**永远先跑一个"已知答案位置"自校验（第 0 字节通常是 `f`）。**
- **payload 里不能有 `0x0a`**：泄漏的 base/canary 是随机的，含 `0x0a` 时会被输入函数的换行截断，表现是"程序正常退出"，完全不像崩溃。构造完 payload 先断言 `b"\n" not in payload`，否则重连重试。
- **`edi` 不一定来自你以为的寄存器**：这题的 CSU 是 `edi = r13d`。写错时 `read` 拿到非法 fd 立即返回，侧信道静默失效。
- **表地址要落在可写段内**：`TABLE + 8*b` 超出映射会 `SIGSEGV`，和"不命中"的现象一模一样，会误导二分。
- **`{` 是 `0x7b`，`}` 是 `0x7d`**：自校验时把期望值记反，会白查半天。
- **靶机重发会换 flag**：旧前缀在新容器上不成立，必须从第 0 字节重来，不要复用。

## 边界

- 依赖"能装 seccomp 但不杀进程"（`ERRNO`）；若默认动作是 `KILL`，ROP 仍在但要慎用任何被拒的 syscall，且不能靠"崩溃 vs 存活"区分（两种都会死）。
- 依赖 `read` 在允许列表里，且 flag 的 fd 已经打开并落在可直接使用的编号上。
- 依赖存在"以数据为下标"的间接调用（`call [reg+reg*8]`、跳转表、`switch` 的 `.rodata` 表）；纯 `ret` 链做不出这种判据。
- 依赖输入函数遇 `\n` 截断或长度可控，否则无法按阶段分段投递。
- 时间成本：单次探测 ≈ 客户端阶段间隔（~1.9 s）+ 存活判定窗口（1.5~2.5 s）；42 字节 flag、5 路并发约 6 分钟，串行则十几分钟。
- 未验证：`KILL` 型 seccomp、非 x86-64、没有包装器（裸监听）的远端 —— 裸监听时"半关闭"判据反而可能是对的，需要按实际接入层再校准一次。
