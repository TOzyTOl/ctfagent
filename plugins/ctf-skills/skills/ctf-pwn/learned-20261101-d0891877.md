# 自定义字节码 VM + 压缩式 GC：1 字节改 kind → stale 指针类型混淆 → 有界任意读写 → native 表 pivot

## 什么时候用

- 服务收的是**字节码帧**而不是文本：4 字节小端长度 + 指令流，dispatch 返回非 0 就断连
  （babel：`read(0,&n,4)`，`1..65536`，坏 opcode/类型错误静默断开）。
- 运行时是 C 壳 + 原生解释器（OCaml/JS），对象带 **tag**：int 是 `n<<1`，
  堆对象是 `(off<<4)|kind<<1|1` —— 指针低位直接编码 kind。
- GC 是**压缩式/移动式**，且只对容器 kind 递归修正元素指针，其他 kind 当叶子。
- seccomp 只放行 `read/write/close/exit/exit_group/openat`：终局只能是 open+read+write。

## 怎么做

**1. 先摸协议和 seccomp，别拿文本硬怼**

断在 `read` 系统调用或 dispatch 上确认帧格式；同时把 main 里的 BPF 序列读出来。
babel 的判据：先发 `u32 len` 再发指令，dispatch 非 0 即断连——**不要**把"没有回显"当成崩溃。
白名单里没有 execve 时，直接按 `open(path,0) → read(3,buf,n) → write(1,buf,n)` 设计。

**2. 把值模型与对象布局钉成表**

至少要写清：tag 规则、每种 kind 的 `+0x10/+0x14/+0x18` 含义、数据区是否内联、
GC 根在哪、**哪些 kind 会被 GC 递归**。babel 的关键是同一语义有两个长度字段：
string `+0x10 = len`、`+0x14 = len+1`，而 op12/op13（`sset` 类）用的是后一个。

**3. 找"长度字段错位"的 1 字节越界**

空串或 concat 结果的 `+0x14 = len+1`，所以 `idx=0` 能通过检查，写入点落在对象末尾——
正好是**下一个堆对象的 kind 低字节**。最小验证：改相邻 array 的 kind 1→4，
然后触发 GC，看后续读到的内容是否变化。

**4. 压缩式 GC 把"改 kind"升级为 stale 指针**

分配顺序 `D(dead array) → R(fnref) → E(空串) → B(array)`，`B[0]=D`，再用越界字节把
`B.kind` 改成 4（叶子）。触发 GC 后 D 被回收、R 压缩到低地址，而 B 被当叶子，
`B[0]` 仍是旧值 → 指向"R 的新位置"。用 array 下标读 `B[0]` 就读出 fnref 的内容：
babel 靠 `+0x18 = &native_table[idx]` 直接泄漏 PIE。
**对齐靠 dead 对象控制，不靠手算**：读一次验证一次，别把偏移写死到算出来的值上。

**5. 伪造 tag 对象 → 有界任意读写窗口**

再放一个内容可控的 string，数据区写入伪对象 `0x409`（`off=0x40, kind=4, tag=1`；
其 `+0x14=-1`、`+0x18=3<8` 满足绑定指令的检查）。第二次 GC 让 stale 值精确指向该数据区，
用 array 读指令取出伪值，再喂给"把 buffer 表 slot 绑定到目标页"的指令
（babel op25 正常路径不可达：正常对象 `+0x14` 不可能是 `0xffffffff`，天生就是给伪造准备的）。
绑定后得到 **±1MB 窗口**的字节读写（babel：基址 PIE+0x58000，窗口长度固定 0x100000）。
先读 `read@got` 泄漏 libc，再读堆基址/计数器做自检（count==3 且 read@got 落在 0x7f 段，
失败就重连重来）。

**6. 控制流：native 函数表覆盖 + 可控寄存器栈迁移**

已有任意写后，把 `native_table[idx]` 改成 libc 的 `mov rsp, rdx ; ret`。
pivot 选哪条取决于调用约定：babel 的 `op_call` 调 native 时 `rdx = &stack[0]`，
所以先用普通 VM 指令把 ROP 链写进数据栈，再 `call` 即完成迁移。
ROP 按 seccomp 白名单写；flag fd 是 3（main 启动时 close(3..63)），路径字符串塞进链尾。

## 坑

- **"检查永远不成立"的指令不要跳过**：它往往是给伪造对象用的入口（babel op25）。
- **GC 只遍历部分 kind**：改完 kind 必须确认目标是不是叶子，否则"压缩后错位"不成立。
- **偏移不要跨实例复用**：堆布局、压缩偏移、GOT/表地址都随构建变化；exp 里保留
  读回验证与 3 次重试，每次重连重新泄漏。
- **本地 libc 必须 pin 到题目版本**：babel 是 `2.39-0ubuntu8.9`，主机 20.04 的 libm 缺
  `GLIBC_2.38` 符号，会表现成 BrokenPipe/无回显。用 `dpkg-deb -x libc6_<版本>_amd64.deb`
  解出整套 `ld/libm/libc`，`ld-linux --library-path` 启动。
- **二进制在 /mnt 下没有 +x**：拷到 ext4 再 chmod，否则 transport 直接失败。
- **栈迁移依赖寄存器而不是 gadget 名字**：先反汇编 native 调用点确认哪个寄存器可控。
- **flag 按容器随机**：本地先打 `/etc/hostname` 验证整链，再打远端 `/flag`；换容器重打。
- **路径长度受限**：链尾槽位只放得下 15 字节路径，超长要换存放位置。

## 边界

- 依赖 GC 是移动/压缩式；标记-非移动 GC 不会产生 stale 错位。
- 依赖"叶子 kind 不修正元素指针"这一实现缺陷；容器 kind 全覆盖的 GC 不适用。
- 依赖 native 调用路径暴露可控寄存器（rdx/rsi）；调用约定不同则换 pivot gadget。
- 依赖 seccomp 白名单含 `openat/read/write`；只有 `read/write` 时要预先打开 fd 或改纯外带。
- 版本敏感：对象布局、opcode 编码、表偏移、libc 偏移全部随版本变化，跨版本必须重新标定。
