# CTFAGENT 使用说明（中文）

> 多 agent 协同的 CTF 解题系统。主 agent 拆题调度，方向 worker 并行执行，独立 verifier 复现 flag，人工确认。

## 1. 它解决什么问题

CTF 比赛中，一道题往往需要多种能力（crypto 要写脚本、pwn 要起 gdb、web 要反复构造请求、forensics 要翻 pcap），而人只有一双手。CTFAGENT 把这些拆成并行的方向 worker：

- **主 agent**：和你对话、判断题目方向、派活、汇总；它不自己打，也**不能自己宣布 flag 成立**。
- **方向 worker**（web/crypto/pwn/reverse/misc/forensics/malware/ai-ml/osint）：各有一个真实 shell、题目附件、对应的 CTF 技能库；边做边把结论写回共享黑板。
- **verifier**：拿到 flag 候选后**独立重新推导**，不信任提交者的脚本。
- **你**：最终确认 flag。系统不会自动提交到任何平台。

## 2. 安装

```powershell
cd D:\agentsec\CTFAGENT
uv venv --python 3.12 .venv
uv pip install --python .venv\Scripts\python.exe -e ".[dev]"
```

模型接入（与 Claude Code 同一套环境变量）：

```powershell
$env:ANTHROPIC_BASE_URL   = "http://127.0.0.1:15721"
$env:ANTHROPIC_AUTH_TOKEN = "..."
```

也可以不碰环境变量：起服务后打开 **凭据页**（`/settings`），填端点 + 令牌，
它会先验证再保存成一张供应商卡片，模型按角色从下拉框里选；换网关点「切换」即可，
下一次派活生效、不用重启。优先级：`CTFAGENT_*` 环境变量 → `config.toml`（凭据页写的就是它）
→ `ANTHROPIC_*` 环境变量 → `~/.claude/settings.json` 的 `env` 段。

自检：

```powershell
.\.venv\Scripts\ctfagent.exe doctor
```

`doctor` 会报：Python 版本、数据库、工作目录、技能库、claude CLI（必须是原生 `claude.exe`，SDK 拒绝 `.cmd/.ps1` 垫片）、沙箱状态、已装的 CTF Python 包。

CTF 常用包建议先装（缺了 `doctor` 会列出来）：

```powershell
uv pip install --python .venv\Scripts\python.exe pwntools z3-solver pycryptodome gmpy2 capstone
```

## 3. 跑一道题

### 命令行

```powershell
# 题目目录里要有 challenge.yaml
.\.venv\Scripts\ctfagent.exe run D:\agentsec\CTFAGENT\challenges\n17

# 跑完会停在「等待确认」，输入 y 确认，或稍后用：
.\.venv\Scripts\ctfagent.exe confirm <flag_id>
.\.venv\Scripts\ctfagent.exe show <run_id>

# 技能沉淀（flag 确认后、显式触发）：把这次解法蒸馏成技术笔记装入技能库，
# 之后该方向的 worker 派发时会看到笔记索引——方法跨题形传递，比赛后批量做。
.\.venv\Scripts\ctfagent.exe distill <run_id>
```

### Web UI（多题并行时用）

```powershell
.\.venv\Scripts\ctfagent.exe serve      # http://127.0.0.1:8788
```

打开就是**对话式首页**：一个输入框，贴题目原文、给目标地址，或者先聊两句都行。附件点「＋ 附件」选，也可以直接拖到页面里（整页会浮出「松手即可附上文件」）；Enter 发送，Shift+Enter 换行。第一条消息就是主 agent 看到的题目描述，不需要 `challenge.yaml`，也不需要先把文件整理进某个目录。

发送后进入工作台：

- 左边是**多任务窗口**，每个 run 一行，点一下切换；运行中排上面，已捕获的整行反转成纸色。每行的标题右端是**开始时间**，下面一行是**已用时间**和花费；鼠标停在时间上能看到完整的起止时刻（还在跑的就写「开始，仍在进行」）。
- 中间是**对话**：你发的话和附件（显示成可点下载的文件卡片）都在，主 agent 的回复逐字流出。跑着的时候可以继续补线索，也可以再上传附件（文件落进 `attachments/`，同时告诉主 agent）。标题下面同样有这次 run 的开始时间和已用时间。
- 右边四个页签：工单、flag 候选（确认/驳回）、共享黑板、实时日志。**每个工单**右上角是它的开始时间、耗时和花费——两个 worker 谁慢、慢在哪一段，看这一行就够。

黑板上的每条记录都带一个**依据**：实测（真的跑过并看到结果）、推导（从观测数据算出来）、推测（读代码或假设）、外部资料（文档/题面/网上）。这是从 REA 搬过来的证据纪律：静态反汇编不能被说成「实测」，验证者据此知道该重点打哪一环。逆向类 worker 还会把「未解问题」单独登记成黑板条目，主 agent 收尾前必须解决或明确放弃——卡住不说比答错更糟。

首页下方的折叠区仍保留目录登记入口，供已有 `challenge.yaml` 的题目使用。

### 比赛接入（CTFd）

顶栏「比赛」页接一个 CTFd 账号：

1. 填比赛名、平台地址、Access Token（CTFd → Settings → Access Token），点「连接并验证」。系统先调 `/api/v1/users/me`，token 无效就不保存。
2. 点「同步题目与附件」：把平台题目拉成本地题目，未解的题连同附件下载到 `workspaces/platform/comp-<id>/<题目 id>/`。重复同步按 `(比赛, 题目 id)` 原地更新，不会重复建行，也不会覆盖手动加的附件。
3. 「全部开跑」或逐题「开跑」。
4. 解出后照常在**工作台**确认 flag；确认之后 flag 卡片上才出现「提交到 <比赛名>」。点它才真正发到平台。

平台返回 `correct` / `already_solved` / `incorrect` 都记成一条回执，显示在 flag 卡片上。错答案只记录不抛错——你据此判断是题面理解错了还是 flag 错了。系统不会自动提交任何 flag。

## 4. 题目格式

```yaml
name: n17
category: crypto            # 可选，不写让 triage 判断
description: |
  一段题面。
remote: "nc 1.2.3.4 31337"  # 可选
flag_format: "[0-9a-f]{32}" # 可选，收窄候选提取
hints:
  - "先看 nonce"
time_limit_s: 2400
source: D:/path/to/attachments   # 可选，附件不在当前目录时用
```

附件（`source` 目录下除 `challenge.yaml` 外的全部文件）会**复制**到 `workspaces/run-<id>/<题目>/attachments/`，原目录不会被改动。

仓库里的 `challenges/` 已放了四个本机题目的清单：`n17`、`silentrotor`、`ooops`、`pier_beacon`。

## 5. 目录结构

```
workspaces/run-<id>/<题目>/
  attachments/         题目附件（只读数据）
  work/                agent 的工作目录，所有脚本和产物在这里
    .claude/skills/    本 run 的技能库（junction / 复制）
  writeup.md           确认 flag 后由 writer 生成
ctfagent.db            SQLite：题目/运行/任务/事实/flag/事件/对话
plugins/ctf-skills/    11 个 ctf-* 技能（MIT）
```

## 6. 关键行为

| 场景 | 行为 |
|---|---|
| worker 提交 flag | 自动派 verifier 独立复现（同一候选只派一次） |
| verifier 判定 reproduced | run 进入 `needs_input`，等你确认 |
| verifier 判定 refuted | 候选标记 rejected，run 继续 |
| 你确认 flag | 派 writer 写 writeup → run 置 `solved` |
| 你驳回 flag | 主 agent 收到驳回原因，继续找 |
| 墙钟/预算耗尽 | 停止派新活，主 agent 做一次收尾总结，run 置 failed |
| 主 agent 调 `ask_user` | run 暂停，等你回复（Web 聊天框或 CLI） |
| 你发消息 | 主 agent 在同一个会话里继续 |
| **主 agent 回合进行中**，你发消息 | 立刻打断主 agent 当前回合（包括卡在 `wait_tasks` 里），先回答你；worker 不受影响，继续跑 |
| **主 agent 在思考** | 聊天框上方出现一条「思考」折叠条，点一下展开看它正在想什么，再点收起 |

打断只针对主 agent。你发消息时它可能正卡在 `wait_tasks` 等 worker，等回合自然结束意味着等最长 120 秒才看到你的问题；现在调 SDK 的 `interrupt()` 把这一回合切断，同一条会话立刻读你的消息并回答，然后接着汇报它原本在等的结果。

打断产生的 `error_during_execution` 与「会话真的挂了」是同一个 subtype，代码用 `terminal_reason`（`aborted_streaming`/`aborted_tools`）加「这次打断是不是我们发的」区分，所以**打断不会结束 run**；被切断那一回合已经流出去的文字不会存成一条消息，Web 上会显示「已打断」并清掉那个半截气泡。

思考条只显示主 agent 的：worker 的推理属于它自己的任务，在右侧任务面板和日志里看。它默认折叠成一行，带当前思考的末尾预览和已完成的段数；展开后是一个最高约三分之一屏的滚动窗口，只保留最近 60 段，完整内容在日志和数据库里。展开/收起状态记在浏览器 sessionStorage 里，刷新后保持。被操作员打断时，正在写的那半段思考会跟半截回复一起丢掉。

时间都按本机时区显示。开始时间取 run 第一次进入 `running` 的时刻（还在排队的显示创建时间），耗时是「现在 − 开始」；跑完的那一刻定住，之后不再变。页面开着的时候耗时每秒自己往前走，不用刷新；刚结束的 run 被你再发一条消息拉起来继续跑时，结束时刻会被清掉，耗时接着算——否则它会把「停了多久」也算成「干了多久」。

## 7. 并发与预算

`config.toml`（`ctfagent init` 生成）或环境变量：

| 配置 | 默认 | 说明 |
|---|---|---|
| `limits.max_sessions` | 6 | 全局同时存在的 claude 会话数（每个约 150–250MB） |
| `limits.workers_per_run` | 3 | 单个 run 同时跑的 worker 数 |
| `limits.max_active_runs` | 3 | 同时执行的 run 数，其余排队 |
| `limits.swarm_max_workers` | 3 | 蜂群模式下板子一次最多开几个方向；实际并行取 `min(它, workers_per_run)`，且同一方向只有一个 worker |
| `limits.run_timeout_s` | 5400 | 单 run 墙钟上限 |
| `limits.run_budget_usd` | 30.0 | 单 run 费用上限（本机代理不计费时该值无效，用 token/轮数控制） |
| `limits.main_budget_usd` | 6.0 | 主 agent 单会话上限，防止它一个会话花掉整轮预算 |
| `limits.task_max_turns` | 150 | 单 worker 最大轮数 |
| `limits.task_budget_usd` | 4.0 | 单 worker 默认费用上限（`role_budget_usd` 可按角色覆盖） |
| `limits.task_timeout_s` | 1800 | 单工单墙钟上限 |
| `limits.stall_timeout_s` | 300 | 模型思考时无事件的判死时间 |
| `limits.tool_wait_timeout_s` | 900 | 工具执行中无事件的判死时间（gdb/docker/WSL 长命令不误杀） |

对应环境变量：`CTFAGENT_MAX_SESSIONS`、`CTFAGENT_WORKERS_PER_RUN`、`CTFAGENT_MAX_ACTIVE_RUNS`、`CTFAGENT_RUN_TIMEOUT_S`、`CTFAGENT_RUN_BUDGET_USD`、`CTFAGENT_TASK_MAX_TURNS`，蜂群另有 `CTFAGENT_SWARM`、`CTFAGENT_SWARM_MAX_WORKERS`。

预算看门狗每 2 秒比一次 `runs.cost_usd`。**并行派活会让花费穿过上限**：`task_budget_usd` 派活时按「角色上限」和「run 剩余」取小，但三个 worker 同时看到同一个剩余额度，各自花到上限，合起来就超了。run 18 就是这样：$30.00 上限，四个 reverse/crypto 工单并行，收盘 $35.78。

**超预算的 run 不能继续对话。** 恢复会话会重置时钟但不重置账本，看门狗下一次轮询就把 run 再关一次——操作员的话发出去了，一条回复都没有（run 18 在 06:59:17 发请求，06:59:23 就写下同一句"超过 $30.00 预算"）。所以现在：
- 工作区页面对这类 run 直接显示「预算已用尽」并禁用输入框；
- 仍然 POST 到 `/api/runs/<id>/chat` 的话，返回 303 + notice，说明「已花 $X / 预算 $Y」，并指出两个出口——新开一次运行，或调高 `limits.run_budget_usd`。

想接着追问，就新开一个 run（题目和工作区都还在），或者在 `config.toml` 里把上限改到自己愿意付的数后重启服务。

## 8. 安全边界（必读）

- 会话以 `bypassPermissions` 运行——CTF 场景不能中途停下等人点确认。
- **唯一的硬边界是 `ctfagent/guard.py` 的 PreToolUse 钩子**：
  - 危险命令黑名单（`rm -rf /`、`mkfs`、`diskpart`、`format`、`shutdown`、下载即执行等）；
  - 写入必须落在 run 工作目录内；
  - 读取/写入 `.ssh`、`.gnupg`、系统目录一律拒绝。
- 这是**防事故的黑名单，不是沙箱**。要真隔离，开 Docker：

```toml
[sandbox]
mode = "docker"
```

- 题目附件是不可信数据；本系统只在隔离或授权环境中使用。
- flag 必须人工确认；提交到比赛平台也要再点一次，系统不自动提交。

## 9. 常见问题

**技能没生效？**
`doctor` 里技能库应显示「11 个」。会话以 `setting_sources=["project"]` + `cwd=work` 启动，技能装在 `work/.claude/skills`。若显示「缺失」或数字为 0，说明 `plugins/ctf-skills/skills/` 下的目录里没有 `SKILL.md`（曾经出现过 11 个空目录），新起的 run 会在事件流里写一条 `run.warning`「技能库为空」。少一两个技能也会告警：每个角色只允许一个技能（`ROLE_SKILL`），run 启动时会核对 `work/.claude/skills/<名字>/SKILL.md` 在不在，缺谁就写一条「角色技能缺失」。

另外，`work/` 下会有一个空的 `.git/`（`HEAD`/`config` 手写，不调 git 命令）。它不用于版本控制，只用来把 `work/` 标成 Claude Code 的工程根：否则向上查找会走出 `workspaces/`，把操作者自己的 `D:\agentsec\.claude\`（34 个技能 + `settings.local.json` 里的 `skillOverrides`）带进每一场会话。实测同一台机器：有这个标记 27 个技能，没有 48 个。所以界面上看到 `.git/` 不要删。

**技能只给了目录，正文怎么进上下文？**
技能分两层：`SKILL.md` 是索引（技术清单，每条链一个文件），`auth-jwt.md` 这类是正文。worker 用 `Skill` 工具加载技能时**只有索引被注入**——134 份历史会话里 `Skill` 调用 63 次，而这些索引链接的 107 个技术分册一次都没被打开，等于 worker 拿着目录在凭记忆做题。

为此给 worker 加了专用工具 `read_skill_doc`（`mcp__worker__read_skill_doc`，已进 `allowed_tools`），只读本方向技能目录下的 `.md`：

| 参数 | 行为 |
|---|---|
| `name="auth-jwt.md"` | 返回正文；单篇超过 24000 字就截断，并告诉你全文多少字、被截掉多少 |
| `name` 写错 | 不报死路，直接返回该技能下**真实存在的文件名列表**，下一次调用就能命中 |
| 传路径（`ctf-web/auth-jwt.md`、`../x.md`） | 只取 basename，跳不出技能目录 |
| `name="SKILL.md"` | 拒绝，索引本来就在上下文里 |

提示词也改了：不再说「按需读它引用的文件」，而是「**索引不是技术本身**，命中条目就先 `read_skill_doc` 打开再动手，换到另一个条目再开一篇；一个方向开 2–3 篇是正常的，通读整个库不是」。实测真实会话里 worker 会自己调（`read_skill_doc({'name': 'auth-jwt.md'})`），返回 8895 字 JWT 正文。想确认某场 run 有没有用上，去 `events` 表搜 `read_skill_doc`。

**ELF 打不了？**
Windows 宿主机不能直接执行 ELF。开 Docker 沙箱，或让 worker 走静态分析 + 远程打（提示词已说明）。

**一个 worker 卡住了？**
`stall_timeout_s`（默认 300s）内模型没有任何事件会被中断并标记 `exhausted`；主 agent 会收到结果继续调度。工具正在执行时用的是更长的 `tool_wait_timeout_s`（默认 900s）——跑 gdb、docker、WSL 里的长命令时静默是正常的，不算卡死。

命令超过 CLI 的 600s 工具上限时，CLI 会把它转到后台并立刻返回 `tool_result`，之后会话静默到后台任务结束。这段时间同样按 `tool_wait_timeout_s` 计，因为编排器跟踪了 `task_started` / `task_updated` / `background_tasks_changed` 里的后台任务集合；卡死报错会写成「后台任务（bg-1）900 秒没有任何事件」。`wait_tasks` 返回的 `live.background` 大于 0 就表示这个 worker 正在等自己的后台作业——安静是在做工，不要因此重派。

**同一方向已经有工单在跑，还能再派一个吗？**
不能。`dispatch_task` 遇到同角色活跃工单会直接返回 `error` 而不是警告。要等它、用 `resume_task_id` 接上它，或者确实需要第二个角度时带 `force=true`。run 15 里警告出现了 4 次、4 次都被无视，四个 transcript 各自把同一个 1312 层压缩包重读了一遍。

**想复现一次运行？**
所有事件都在 `ctfagent.db` 的 `events` 表，`ctfagent show <run_id>` 可看任务/事实/flag；工作目录保留全部脚本与产物。

## 10. 基准集：证明平台真的在变强

战例库会在每次运行结束时把过程蒸馏成一张卡，同类题的下一轮会带上前车之鉴（含那一轮**没解开的问题**）。卡片被运行加载后会记账：那一轮解出记一次帮助，失败记一次拖累；一张卡至少经历两轮裁决，才会在检索排序里加减分。因此库不会无限膨胀成噪音。

题目的方向由 triage 自动落库：粘贴建的题不带分类也没关系，triage 工单结束时它的结论会写进题目记录（只补空缺，**不会覆盖平台同步或你手工给的分类**）。所以从第二次运行起，同类题就能靠方向匹配上战例卡——这是「做过的题越做越顺」的前提。

这些改动是否真的有效，只能靠固定题集的比分回答：

```powershell
# bench/bench.yaml 列题目目录与已知答案（expect 或 expect_regex）
.\.venv\Scripts\ctfagent.exe bench bench
.\.venv\Scripts\ctfagent.exe bench bench --library ctfagent.db   # 带上训练出的战例卡再考
.\.venv\Scripts\ctfagent.exe bench bench --baseline bench\results\bench-20261001-120000.json
```

三条诚实规则：**基准运行不产生训练数据**（每次调用新建数据库，跑完即丢），**判分只认提交值与答案是否相符**（不认置信度、不认「几乎肯定」；`flag{...}` 包装在比较时剥掉，`flag{X}` 与 `X` 视为同一个值），**worker 读不到答案**——基准目录、训练库 `ctfagent.db`、`--library` 指定的库在运行期间全部封禁，题目自己的原始材料目录可以在 `bench.yaml` 里用 `sealed:` 逐题封掉。答案未知的题不能进基准集——判错一个答案比不判分更糟。

只有确知答案、且答案不会变的题才进来；同一批题隔一周再跑，`--baseline` 会逐题列出翻转（`← 结果翻转`），因为平均分上涨而某道题从解出变成不解出，正是最需要看到的变化。

结果每跑完一题就写进 `bench/results/bench-<时间戳>.json`，不是等全部跑完才写——
基准花的是真钱，中途崩了不该连已经跑出来的结果一起丢。单个块也可以单独跑：
`--only lcg_step,aes_pin`（逗号分隔），崩了不影响别的块。

基准集现有 8 题（2026-10-24 起）：easyrs、n17 之外是 6 道自造题（lcg_step / aes_pin /
rsa_broadcast / crackme_z3 / rsa_wiener / sha256_ext，难度从易到难），材料在
`bench/challenges/`，生成器、求解器和答案在 `bench/sealed/`——跑基准时整个 bench
目录对 worker 封禁，答案不可能被读到。**自造题不要在正常训练中跑**：它们的战例卡
一旦进训练库，基准测的就变成记忆而不是能力。改了生成器之后重跑对应 `gen.py` 并确认
`tests/test_bench_challenges.py` 仍是绿的（它守着 manifest 与答案的一致性、每题可解性）。

`sealed:` 用分号分隔多个路径，相对路径按 `bench.yaml` 所在目录解析：

```yaml
  - name: n17
    directory: ../challenges/n17
    expect: 8a6179153fd89b40b1eac51e3bc6825f
    sealed: "D:/agentsec/ctf_n17"   # 原始目录里有 answer.json 和 solve.py
```

附件里带答案的题，要么把 `challenge.yaml` 的 `source:` 指向一份筛选过的材料副本（`challenges/n17/materials/` 就是这样来的），要么整题剔除。

## 12. 记忆闭环：卡、笔记、体检

平台有两条记忆，分工不同：

- **战例卡**（`cases` 表，自动）：一次运行结束时蒸馏成一张卡，记录这条路怎么走通/走死。
  下一道同类题会在提示词里看到它；
- **技术笔记**（`learned-*.md`，显式）：把一次**已确认 flag** 的解法蒸馏成面向方法的笔记，
  装进对应方向的技能目录，之后该方向的 worker 派发时能看到索引，用 `read_skill_doc` 打开。

### 「用了才算」：help/harm 怎么记

卡和笔记都只有在自己写下的东西里**真的出现**才算被用：卡里的技法词、笔记自己的词汇，
至少两个出现在这次运行的黑板事实、工单结论或 flag 推导里。加一次性的记账位，
一次运行只结算一次。

为什么要改：旧规则记的是**曝光**。实测库里的卡 #15 记着 5 次帮助 0 次拖累，
而它所在的 5 次运行里 4 次失败——它只是被放进了提示词。于是越没用的卡看起来越有用，
检索把更吵的排在前面。

`ctfagent memory` 打印闭环当前的样子（卡数、方向 unknown 数、库内样板词、已裁决运行数、
有记账的卡、各方向笔记与用量、未分类题目的实际检索命中）。**沉默失败只有它会报。**

`ctfagent recount` 按新规则重判历史运行（默认只打印会改什么，加 `--apply` 才落库）。
2026-10-27 已对实时库执行一次：卡 #15 由 +5/-0 变 +0/-0，卡 #18 由 +2 变 +1。

### 方向从哪里来

题目方向决定卡和笔记的归属，来源有三条，优先级从高到低：

1. 平台同步或手工给的分类（永不覆盖）；
2. triage 工单的 `category=<方向>` 结论；
3. **兜底**：triage 没跑时，用轮数最多的 worker 角色，且该角色至少跑了 10 轮。
   收尾会取消在跑任务，轮数接近 0 的角色不是证据，错方向比 unknown 更糟。

### 沉淀笔记的两个入口

```powershell
.\.venv\Scripts\ctfagent.exe distill <run_id>   # 命令行
```

运行页「沉淀笔记」按钮（只在有已确认 flag 时出现）功能相同。
想让确认 flag 时自动做，把 `config.toml` 的 `[limits] distill_on_confirm` 改成 `true`
（默认关）：它会起一个 writer 会话，比赛里通常赛后批量做更划算。
沉淀失败只写一条 `skill.note_failed` 事件，不会影响这次运行的结果。

### 基准与记忆的隔离

基准必须测能力、不是测记忆，所以：

- 战例卡只在 `--library <db>` 显式指定时才带进基准（`prepare_db` 新建库只复制 `cases` 行）；
- **技术笔记是文件**，默认**剥掉**：基准跑在自己的技能目录副本上，训练出来的 `learned-*.md`
  不会进基准的提示词，基准自己蒸馏的笔记也写不进实时技能库；
- `--notes <dir>` 是显式的「带着训练笔记来考」开关，summary 里会写清用的是哪一种。

```powershell
.\.venv\Scripts\ctfagent.exe bench bench                          # 裸考（无卡无笔记）
.\.venv\Scripts\ctfagent.exe bench bench --library ctfagent.db     # 带战例卡
.\.venv\Scripts\ctfagent.exe bench bench --library ctfagent.db --notes plugins\ctf-skills\skills
```
