## 1. 做到了什么

### 1.1 token 层（`app.css` 第 1–70 行）

`color-scheme: dark` 移进 `:root`（原来是一条独立的 `:root { color-scheme: light }`，已删除）。三档地面 `#070a0e / #10151c / #1a212b`，档与档只差 1.08:1 与 1.13:1——层次靠发丝线和 1px 内高光（`--lit-edge`），不靠明度跳跃，因为深底上投影读不出来。

纸是**独立的一套 token**（`--paper-*`），不是把暗色值取反：暗色值在纸面上普遍 1.0–1.9:1。

### 1.2 三处结果面改成纸

| 位置 | 之前 | 现在 |
|---|---|---|
| `.docket.captured`（已捕获工单行） | 深绿满铺 + 白字 | `--paper-sheet` 渐变 + `--paper-ink` 墨字 + `--paper-lift` 投影 |
| `.rail-item.captured`（任务轨已捕获行） | 同上 | 同上 |
| `.flag.f-confirmed`（已确认 flag 卡） | 同上 | 同上 |
| `.writeup`（报告正文） | 白纸 | 同一张纸，但用**自己的** `--paper-rule` 分隔线和高亮阶梯 |

`.writeup` 的 `code` / `pre` / `table` / `a` 全部换到 `--paper-*` 家族——暗色 token 在这张纸上只有 1.0–1.9:1，漏进去任何一条都是不可读的。

### 1.3 白底时代的语义失效点（这一轮真正修掉的 bug）

**`.docket:hover` 是个空操作**：它把底色从 `--board-2` 改成 `--board-2`（工单行本来就坐在 `--board-2` 上）。改成 `--board-3`——整行是"往上抬一格"，不是"往旁边挪一格"。

**已捕获行的"当前"标记在纸上消失**：`.rail-item.on` 用左边一道 1px 冷白边标记当前打开的运行。运行一旦被捕获，整行变成纸，冷白边在纸上等于没画（实测计算值 `border-left` 在纸面上不可辨）。补 `.rail-item.on.captured { border-left-color: var(--paper-ink) }`；窄屏把左边线换成下边线的那条规则同理，用 `--paper-ochre`（纸上 ochre 是 `#6b4a10`，6.74:1；深色的 `#e0a04a` 在纸上只有 1.9:1）。

### 1.4 窄屏上真正修掉的两个溢出

这两个都是**布局 bug，不是配色问题**，在旧的白底版本里就已经存在，只是没有宽内容触发它：

**`.doc-wrap` / `.page` 缺 `width: 100%`**。它们是 `.frame` 这个列向 flex 的子元素，横向的 `margin: auto` 会取消 stretch，盒子于是按 fit-content 取宽——说明页里一段 `pre` 有多宽，整个文档就有多宽。实测 320px 视口里 `.doc-wrap` 撑到 456px，`pre { overflow-x: auto }` 永远轮不到出手，整页横向滚动。加 `width: 100%` 后 320px 溢出归零。

**`.composer-bar` 不换行**。320px 下这一行的自然宽度是 332px，盒子只有 274px（附件 34 + 文件夹选择 133 + 键帽提示 69 + 按钮 56 + 四个 10px 间隙），`nowrap` 让溢出直接漏到 composer 外面。改 `flex-wrap: wrap` + `gap: 8px 10px`。宽屏上它完全不生效，只在真的放不下时才启用；按钮的 `margin-left: auto` 保证换行后它仍在本行右侧。

## 2. 对比度：两条阶梯，全部实测

单位是 WCAG 对比度。**深底看最亮的一层（`--board-3`）**，因为深底下越往上的面浅色字越弱——这和白底时代的方向完全相反（白底最暗的一档最弱）。

| `--chalk` `#e8eef4` | 16.97 | 15.68 | **13.86** |
| `--chalk-dim` `#a9b6c2` | 9.59 | 8.86 | **7.84** |
| `--chalk-faint` `#94a2b0` | 7.61 | 7.03 | **6.21** |

强调色在 `--board-3` 上：ochre 7.17、blue 8.11、green 7.69、red 5.94、green-edge（非文字）4.2。

|---|---|---|---|
| `--paper-ink` `#0c110f` | 17.20 | 15.98 | **14.65** |
| `--paper-dim` `#3f4a45` | 8.33 | 7.74 | **7.10** |

| 对 | 比值 |

### 2.4 怎么量的

不是算的，是**在渲染后的页面上量的**：脚本遍历每一条可见文本节点，沿祖先链解析出实际画上去的底色（含渐变——取最暗的一档作为最坏情况），再算比值。两套探测器各自带阳性对照：

- 暗地探测器：注入 `#3a4450` 在 `#070a0e` 上（实测 2.00:1）与 `#e8eef4`（16.97:1），前者必须被判 FAIL，后者必须通过——实跑前者 2.00 判 FAIL、后者 16.97 通过
- 纸面探测器：在真纸上注入 `#8a8a86`（2.67:1）与 `#ffffff`（1.19:1），两条都必须被判 FAIL——实跑两条都 FAIL

结果：**六个路由、暗地 659 条不同文字样式、纸面 180 条，低于 AA 的为 0**。两边最弱的各有一条：暗地 5.34:1（命令面板键帽上的 `--chalk-faint` 压在 `--key` 上），纸面 5.39:1（`.stamp.st-confirmed` 的纸上绿压在纸最暗的一档上），都高于 4.5 的门槛。

## 4. 明确没做 / 不要顺手做

1. **没有删死 CSS**：`.docket*`、`.board*`、`.run-list`、`.run-main`、`.chosen-item`、`drop-hint`、`just-captured` 仍在（上一轮就记着）。这轮只是把它们的颜色跟着 token 走，删了没有收益、有风险。
2. **没有做"暗色/浅色切换"**。这一版的世界观建立在"只有纸是亮的"上，加一个浅色主题等于让整块板都变成纸，语法就废了。
3. **没有给暗地加任何发光**：`text-shadow` 光晕、霓虹描边、带色投影一律不用。ui-ux-pro-max 的 "Dark Mode (OLED)" 方案建议 `text-shadow: 0 0 10px` 的极弱发光，被明确拒绝——它会把视线从纸上拉走。
4. **没有换字体**：Bahnschrift / Cascadia Mono / Sitka 都是 Windows 自带并已确认存在，换掉是纯粹的无谓动作。
5. **模板和 JS 一行没动**：所有结构、事件流、命令面板、SSE 全部保持原样。

## 5. 教训（下次直接用）

- **深色化不是取反**。把 `#f4f6f2` 取反得到的是 `#0b090d`，但浅底上的 `#4c5459`（次要文字）取反后是 `#b3aba6`——看着对，实际上所有"色相"关系全断了。正确做法是重定一套，然后**逐条量**。
- **深底上"越亮的面"是文字最弱的地方**，白底上是"越暗的面"。所有对比度都要在最亮的那一档上验。
- **浅色主题里的"当前项"标记（冷白边、亮底）在纸上会消失**。任何在结果面上叠加的状态（选中、焦点、悬停），都要单独给纸面一条规则。
- **横向溢出先怀疑 `margin: auto` + flex**：列向 flex 的横向 auto margin 会关掉 stretch，容器尺寸跟着最宽子元素走，`overflow-x: auto` 完全轮不到。症状是"只有这一页、只有这张有代码块时溢出"。
