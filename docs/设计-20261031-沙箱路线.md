# 沙箱路线设计（P1，2026-10-31）——实现前必读

> 状态：**设计定稿，未实现**。本文档记录两条被否掉的路和一条选定的路，
> 以及那个差点让人白干一晚的 SDK 限制。实现者从这里开始。

## 目标

`sandbox.mode = "docker"` 现在只是提示词开关。目标：worker 的全部命令真实跑在
容器里，宿主机只保留编排层。完成后处理不可信附件（malware 类）才算过关。

## 两条被否掉的路

### ✗ 命令重写（PreToolUse 钩子把每条命令包成 `docker run …`）

- worker 在 Windows 宿主上用的是 **PowerShell 工具**（CLI 按宿主命名 shell 工具），
  命令是 PowerShell 语法；kali 容器里是 bash——每条命令都要翻译，翻译器本身就是
  一个永远修不完的 bug 源；
- cwd、路径（`D:\...` vs `/work`）、NO_PROXY 语义全都要重映射；
- 容器外层每命令 0.3-1s 启动开销 × 每场 100-200 条命令。

### ✗ `cli_path` 指向包装脚本（`docker run … claude "$@"`）

- **SDK 拒绝 `.cmd/.ps1` 垫片**（`settings.py` 的验证 + `doctor` 明说必须是原生
  `claude.exe`）。Windows 宿主上包装脚本只能是 `.cmd`/`.ps1`——这条路在 Windows
  上被 SDK 焊死了。写成 `.exe` 需要引入编译工具链，为一个垫片不值。

## 选定的路：整个 CLI 会话跑进 WSL2

WSL2 是本机现成的真 Linux 内核（pwn 工具链已装在 Ubuntu-20.04 里），
`wsl.exe` 是原生 Windows 可执行文件——能通过 SDK 的垫片检查。

### 前置（一次性，在 WSL 内）

1. Node 20+（WSL 里没有，`nvm` 或 apt 装）；
2. `npm i -g @anthropic-ai/claude-code`（WSL 内的原生 Linux CLI）；
3. CTF python 工具链装进 WSL 的 python3（现有 3.8 偏老，建议 uv 装 3.12）。

### 接线（平台侧，约 60 行 + 测试）

1. `config.py`：`SandboxConfig` 增加 `wsl_distro: str = ""`（空 = 不启用）；
   `mode = "wsl"` 成为与 `"docker"` 并列的真实选项；
2. `backend.py`：`mode=wsl` 且 distro 非空时，`cli_path` 解析为
   `C:\Windows\System32\wsl.exe`（或 `shutil.which("wsl")`），并在 `_options`
   里追加一个**参数前缀**机制——SDK spawn 的 argv 变成
   `wsl -d <distro> -e <WSL 内 claude 路径> <原参数…>`。
   **关键**：SDK 是否支持 argv 前缀（而非仅 cli_path 整体替换）需要先做一次
   10 分钟的验证实验——不支持的话，就绪一个原生小 exe 转发器（Go/Rust 50 行，
   转发 argv 给 wsl），这是本文档唯一需要用户拍板的分叉；
3. `cwd` 传 WSL 路径（`\\wsl$\Ubuntu-20.04\work\...` 或让 run 工作区直接建在
   WSL 文件系统内——**推荐后者**，/mnt 挂载的性能和权限坑是已知的）；
4. `guard.py`：wsl 模式下路径归一化按 WSL 规则（`/work`），危险命令黑名单不变；
5. `doctor`：wsl 模式下检查 distro 内 node/claude/工具链。

### 为什么不用 docker（虽然 Docker Desktop 就在机器上）

docker desktop 的 CLI 也是 Windows 进程（同样被垫片限制卡住），且容器 per-session
常驻需要 volume 管理会话 transcript。WSL 路线复用已有的发行版和工具链投资，
`wsl.exe` 是系统原生 exe。**docker 路线留给"第二个人在 Linux 宿主上部署"的场景**——
Linux 上 cli_path 直接指向容器内路径或原生 wrapper，没有垫片问题。

### 验收标准

- [ ] worker 的一条 `python solve.py` 真实跑在 WSL（`/proc/version` 可证）；
- [ ] 宿主机进程树里没有直接执行解题命令的 PowerShell；
- [ ] guard 的黑名单用例在 wsl 模式下全部保持 DENY；
- [ ] 基准 8 题 WSL 模式重跑一遍，分数不塌（成本 ±20% 内）。
