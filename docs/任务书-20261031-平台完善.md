## T1 外部看门狗 + 自动修复【本批执行】

**问题**：run 82/88 证明进程内的看门狗会随运行的任务树一起死——run 82 卡 running 半天、
run 88 的验证器冻结 18 分钟，都是"看门狗自己也是死者"的形态。需要**进程外**的独立
看门狗：它读数据库而不是读内存，任何进程内时钟失效都逃不过它。

**行为**（`ctfagent.watchdog`，单次执行 `python -m ctfagent.watchdog`）：

| 场景 | 动作 |
|---|---|
| run `running` 且事件流静默 > 45 分钟（超过进程内一切时钟的合法上限） | 收割非终态任务行（stopped，注明来源）→ run 标 interrupted → **自动复活**：向服务 POST 一条看门狗消息，触发 run.reopen，lead 从原对话继续 |
| run `needs_input` | 不动（等人是合法状态） |
| run `queued` | 不动（排队是合法状态） |
| 服务不可达（/api/health 失败） | 只修库，不尝试复活（复活需要服务活着） |

**复活护栏**：每个 run 最多自动复活 2 次（状态文件记录）；预算耗尽的 run 不复活
（复活只会立刻被看门狗再关一次）；复活消息写明是看门狗所为。

**验收**：静默的 run 被收割 + 中断 + 复活消息发出（服务活着时）；新鲜的 run 不被碰；
有 pytest。
