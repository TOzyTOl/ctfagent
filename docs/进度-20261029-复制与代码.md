## 1. Flag 卡：为什么是按钮，不是"点一下文字就复制"

模板里加的是一个真 `<button>`：

```html
<div class="value-row">
  <div class="value" data-copy="{{ f.value }}">{{ f.value }}</div>
  <button class="copy-flag" type="button" aria-label="复制 flag">复制</button>
</div>
```

- **不可见的点击区没人找得到。** flag 是这个产品唯一的产出物，操作员一晚上要复制几十次；把点击目标藏在一行等宽文字上，等于给了一个不会被人发现的快捷键。
- **文字本身仍然可选**，想拖选的人不受影响。
- **事件是委派的。** 监听挂在 `document` 上（`.copy-flag` → 最近的 `.flag` → 兄弟 `.value` 的 `data-copy`），因为右侧栏的页签切换、运行切换都可能让它重新渲染，逐个绑定会漏。`data-copy` 也顺手挡掉了 `textContent.trim()` 可能带出来的空白。
- **纸上、暗地上两套墨。** 未确认的卡片在地面上：按钮 `--chalk-faint`（实测 8.05:1），悬停升到 `--chalk`；已确认的卡片是纸：按钮 `--paper-dim`（7.10:1），悬停 `--paper-ink`。

## 2. 代码块：一条栏 + 一块凹板

```
┌ python ─────────────────────────────── 复制 ┐   ← .code-bar（--board-2，控制条）
│ assert standard_dec("ABC") == "ZYX"          │   ← .code-block（--board，凹进去）
└──────────────────────────────────────────────┘
```

- **栏是控制条，不是代码。** 所以它比代码板亮半档（`--board-2` 对 `--board`），底部一条 `--rule-soft` 分隔；它上面的字是"关于这段代码的"，所以语言标签走等宽 + 字距。
- **壳不能 `overflow: hidden`。** `pre` 自己 `overflow-x: auto`，长行的滚动条必须能出来；壳把它裁掉就等于把代码裁掉。栏的圆角因此只有上面两角。
- **`.code-block > pre` 要显式中和四条旧规则。** `.writeup pre`、`.docs pre`、`.msg .body.md pre` 的优先级都比裸 `.code-block > pre` 高，所以中和规则把这四个选择器全列出来，把 margin / border / radius / background 归零，否则代码板里会套着一块"板上的板"。
- **语言标签永远不空**：没有语言的围栏显示 `code`。

### 2.1 七个色位，两套取值

| 色位 | 暗地代码板（`#070a0e`） | 纸面代码板（`#d3d7d1`） |
|---|---|---|
| 关键字 `--code-k` | `#b6a8dd` 9.10 | `#463b74` 6.74 |
| 字符串 `--code-s` | `#d4c08f` 11.08 | `#6b5312` **5.02**（最低） |
| 数字 `--code-n` | `#8fb8c9` 9.32 | `#2b5560` 5.61 |
| 注释 `--code-c` | `#8494a3` 6.37（最低） | `#3f4a45` 6.33 |
| 类型 `--code-t` | `#8ec5b4` 10.20 | `#1d5a4a` 5.51 |
| 调用 `--code-f` | `#9fc0e8` 10.56 | `#1f4d75` 6.06 |
| 装饰器 `--code-d` | `#c9a3c9` 9.03 | `#6a3a6a` 5.94 |

- **纸面必须单独取色。** 暗色值直接搬到纸上只有 1.0–2.0:1（例如 `#b6a8dd` 在 `#d3d7d1` 上约 1.5）。这不是"调亮度"，是两套独立的颜色，只是语义相同。
- **纸面板的最坏底色是算出来的，不是猜的**：`rgba(12,17,15,.055)` 压在纸最暗那一档 `#dfe3dc` 上得 `#d3d7d1`。测量脚本里是按这个公式展平 alpha 再算比值的。
- **注释色在两套里都刻意压到 6 出头**：注释该退后，但不能退到 4.5 以下。

### 2.2 高亮的边界

- **没有语言的围栏不高亮。** `NO_HIGHLIGHT = {"", text, txt, plain, plaintext, output}`——这些是**粘贴的结果**（接口返回、命令输出），给一段 `{"ok":true}` 上色等于暗示它是源码。
- **先转义，再切词。** `highlight()` 的第一步是 `escapeHtml`，之后所有切片都在已转义的串上做，因此不可能从代码里"长出"标签。
- **令牌的判定只看局部：**
  - `tk-c` 注释：`#` 开头（python / ruby / yaml / bash / ps1 / toml / ini / r / pl 这些语言的注释符；字符串优先切分，所以 `"#不是注释"` 不会误判）
  - `tk-s` 字符串：`"`/`'`/反引号成对，转义引号跳过
  - `tk-n` 数字：`\b\d+\.?\d*\b`
  - `tk-k` 关键字：`KEYWORDS` 表里命中且不是属性访问（前面不是 `.`）
  - `tk-f` 调用：标识符后面紧跟 `(`
  - `tk-t` 类型：`^[A-Z][a-z0-9]` 且前面不是 `.` `$` 或标识符字符
  - `tk-d` 装饰器：前面是 `@`
  - 顺序是 **注释 → 字符串 → 词/数**，所以字符串里的 `#`、注释里的引号都不会互相污染。
- **`textContent` 是唯一的复制来源。** 高亮后的 DOM 里全是 `span`，`innerHTML` 会把标签一起复制走。

## 3. 两个渲染器必须吐出同一份标记（这一轮的硬约束）

`ctfagent/mdrender.py`（服务端，刷新时走）和 `app.js` 的 `renderMarkdown()`（流式时走）各写了一遍围栏处理。两边的规则：

```python
# mdrender.py
rest = line.lstrip().lstrip("`").strip()
rest = rest.split()[0] if rest else ""
lang = re.sub(r"[^A-Za-z0-9+#._-]", "", rest)[:24]
return lang if re.match(r"^[A-Za-z][A-Za-z0-9+#._-]*$", lang) else ""
```

```js
// app.js
var rest = line.replace(/^\s*/, "").replace(/^`+/, "").trim();
rest = rest ? rest.split(/\s+/)[0] : "";
var lang = rest.replace(/[^A-Za-z0-9+#._-]/g, "").slice(0, 24);
return /^[A-Za-z][A-Za-z0-9+#._-]*$/.test(lang) ? lang : "";
```

- **为什么要有这层白名单**：这个值最后落进 `class="lang-x"`。围栏行是模型写的，没有任何东西保证它是干净的语言名。```` ```"onmouseover=x ```` 的第一版实现会产出 `onmouseoverx`——不是注入（引号已经被滤掉），但它仍然是一个由乱码变成的类名，而首字母是数字的（```` ```9lives ````）连选择器都不合法。现在先按 `[A-Za-z0-9+#._-]` 收缩，再要求首字母是字母；不满足的**整段丢掉**，围栏就退化成没有 class 的普通代码块。留下 `onmouseoverx` 这种串时它只是个无害的类名，高亮按通用规则走（不代表它真是那个语言，也没有任何"猜语言"的动作）。
- **为什么不加 `lang-` 时保持逐字节相同**：`tests/test_chat_markdown.py` 里有对 `"<pre><code>flag{x}</code></pre>"` 的精确断言。不带语言时输出仍然是 `<pre><code>…</code></pre>`，加了语言才是 `<pre class="lang-python"><code>…</code></pre>`。**这个约束的真正理由是刷新不能改变消息的形状**：如果两个渲染器有一点不一致，同一条消息在流式时和刷新后会长得不一样。
- **说明页的两块代码也标了语言**（`<pre class="lang-bash">`、`<pre class="lang-yaml">`），所以它们同样有栏、有高亮。

## 4. 只装饰"写下来的那条消息"

- `appendMessage()` 里 `if (role === "assistant") decorateCode(body);`——**消息落定后**才挂栏、才上色。
- `loadWriteup()` 在 `target.innerHTML = renderMarkdown(text)` 之后调一次 `decorateCode(target)`。
- **流式气泡不装饰**：`appendDelta` 每来一个 token 就 `body.innerHTML = renderMarkdown(...)` 整个重建，在那里挂栏会被一秒拆装几十次。
- **`pre.console` 显式跳过**：事件日志已经用自己的颜色分类型，再套一层代码高亮是两套语法叠在一起。
- `data-decorated` 保证重复调用不重复包壳（报告页签来回切时会重复 `loadWriteup`）。

## 5. 顺手修掉的一个旧 bug：报告页在手机上被长代码撑宽

`.pane-report .writeup` 原本是：

```css
.pane-report .writeup { margin: 20px auto; max-width: 820px; flex: none; }
```

`.pane-report` 是**列向 flex**，而这行横向 `margin: auto` **关掉了 stretch**，盒子于是按 max-content 取宽。`pre { overflow-x: auto }` 不会改变它的固有宽度——`pre` 有多宽，整份报告就有多宽。

实测（`/runs/77`，320/390px 视口）：`paneClient 372`、`paneScroll 712`、`.writeup` **684px**。整份报告只能拖动才能读。这一条**与这一轮的新代码无关**：把新加的 `.code-block` 壳全拆掉（回到旧标记）宽度一模一样，是旧版就有的塌陷。

修法：

```css
.pane-report .writeup { width: 100%; margin: 20px auto; max-width: 820px; flex: none; }
```

- `width: 100%` 让它以可用宽度取宽；`max-width: 820px` 仍然在宽屏上让它居中。
- 复测：320 → 274 / 302；390 → 344 / 372；760 → 714 / 742；1920 → 820 宽、左右各留 229 居中；1280 → 718 满宽。`paneScroll == paneClient` 三档全部相等。
- 这跟 `.doc-wrap` / `.page` 是同一条坑，说明页那节早就记过一次（`界面设计.md` 的说明页一节）。这次是同一个形状在第三个容器上复发。

实测（键盘模态下 `document.querySelector(...).focus()` + `:focus-visible` 为真）：

| 控件 | 修前 | 修后 |

## 8. 教训（下次直接用）

- **横向 `margin: auto` 会关掉 flex 的 stretch。** 列向 flex 的子元素想"居中但不超过 N px"，必须同时写 `width: 100%` 和 `max-width`；只写前者会满宽，只写后者会按 max-content 塌成内容宽度。这个项目里已经踩了三次（`.doc-wrap`、`.page`、`.writeup`），下次看到"窄屏整页横向溢出"先查这条。
- **改 CSS 后 CDP 的 `Network.setCacheDisabled` 不够。** 必须 `Page.reload` + `ignoreCache: true`。否则你会拿到旧样式，然后花时间调试一个已经修好的 bug。
- **两个渲染器 = 一条约束，不是两份代码。** 任何一边的标记变化都要在另一边逐字对应，包括"什么都不写"的情况。
- **合成 `el.click()` 不是用户手势**，`execCommand('copy')` 在它下面会失败——所以测"退路可用"必须用 CDP 派发真实鼠标事件（`Input.dispatchMouseEvent`，`mousePressed` + `mouseReleased`）。
- **对比度要按实际底色算，不是按 token 名义值。** 这一轮有两处底色是**算出来的**：纸面上的代码板是 alpha 墨压在纸的最暗档上，暗地的代码板是比板面还低一档的 `--board`。拿错底色，七个色位全都不作数。
- **焦点环也要按表面量，而且 `focus()` 量不到它。** `:focus-visible` 只在键盘/脚本显式切到键盘模态时才匹配；直接调 `el.focus()` 量到的是 `outline-style: none`，看上去像"没有焦点样式"，其实是没进那个模态。先派发一次 Tab 再量。
