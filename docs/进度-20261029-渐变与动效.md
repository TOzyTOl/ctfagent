## 3. 动效：只有一个被作者写下来的时刻

### 3.1 曲线

```css
--ease: cubic-bezier(.22, 1, .36, 1);
```

指数缓出、尾巴长：多数距离在前三分之一走完，所以东西是**被放到位**的，不是滑过去的；最后收得慢，所以它是停稳而不是刹住。**不用弹簧、不用回弹**——这是一张调度台，弹一下是它不会讲的笑话。

### 3.2 那一件：结果落纸（`sheet-settle`，340ms）

```css
@keyframes sheet-settle { from { transform: translateY(-6px) scale(.985); } to { transform: none; } }
```

一张刚被放下的纸：来得略高、略小，然后落定。**它不淡入**——一张印出来的行要是会淡入，就像它是没印上去的；**投影也不动**——厚度是纸本来就有的，不是它挣来的。

难点在"它只在真的发生了的时候播一次"：纸是**服务端渲染**的，如果动画挂在元素上，每次刷新都会把屏幕上所有已解出的行重播一遍。做法：

1. `flag.confirmed` 的 SSE 事件到达时，`noteCapture(runId)` 把 run id 写进 `sessionStorage["ctfagent.captured"]`（不是 `localStorage`——这是"这个标签页的下一次绘制"，不是这台机器的事实）；
2. `reloadSoon` 把页面刷到新状态，服务端产出那张纸；
3. 新页面 boot 末尾 `playCaptures()` 读出、**立刻删掉**这个键，只给那一行加 `.just-captured`；
4. 2 分钟的截断窗口：超过它就是过期条目，不播（否则五分钟前的结果会在某次刷新时突然跳一下）。

### 3.3 这一轮真正花时间的那个坑

**任务轨每 5 秒自己 `fetch("/api/rail")` 并把 `#rail-list` 整个 `innerHTML` 换掉——而启动时那一次刷新恰好落在动画播放途中。**

实测追出来的时间线（CDP，`Page.addScriptToEvaluateOnNewDocument` 里挂 MutationObserver）：

```
t=72ms    class 变更：rail-item captured → rail-item captured just-captured   ← 标记加上了
t=92ms    rail-list childList：+7 / -7                                       ← 整个列表被换掉，标记随旧节点消失
t=2600ms  .rail-item.just-captured 数量：0
```

所以不是选择器错、不是服务端 JS 没发到、不是 CSS 动画没定义——那三条都被单独排除了（手动加类后 `animationName` 确实是 `sheet-settle`）。是**标记加在了马上就要被丢弃的节点上**。

修法：id 在模块里多留 `CAPTURE_WINDOW = 1500ms`，`applyCaptureMarks()` 在每次列表换完后再补一次；到一个 `setTimeout` 把 id 删掉、把类也摘掉，**之后不再补**。

不摘掉会怎样，实测过：一个五分钟前的结果会在每次轮询时重新跳一下（`t=8.5s` 仍然是 `just-captured` / `sheet-settle`）。摘掉之后：

| 时刻 | 状态 |
|---|---|
| t=0.8s（窗口内） | `just-captured` = `['78']`，`animationName: sheet-settle` |
| t=2.0s（窗口已关） | `[]`，`animationName: null`，纸本身还在（21 行 captured 不变） |
| t=8.5s（强制刷新过一次） | 仍然是 `[]`——不再复活 |
| 无种子（对照组） | `[]`，什么也没播 |

### 3.4 其余三处都只是**状态变化**

| 动效 | 时长 | 为什么值得 / 为什么不能再长 |
|---|---|---|
| `palette-in`（命令面板出现） | 160ms | 面板是盖在页面上的一层，2% 的抬升读作"从前面来"。再长一点，那个全部职责是"立刻"的控件就要让人等 |
| `ink-in`（新消息 / 新日志行 / 新 worker） | 200ms | 位移 2px：够看出"这行是新的"，小到一屏繁忙日志不会跟着起伏 |
| hover / focus 过渡 | ≤120ms | 只过渡颜色 |

`ink-in` 的"只有新的才动"是三个不同的判据，都得有：

- 日志：`appendEvent(kind, payload, createdAt, enter)` 多一个 `enter` 标志，**只有 SSE 实时流传 `true`**；`initConsole` 里回放的服务端积压永远是 `false`（否则每次进页面八十条事件一起闪）。
- 消息：`appendMessage` 追加的气泡带 `just-in`；服务端渲染的已经在页面上，不带。
- worker 条：`renderLive` 每次都整条重建，所以"新"必须来自**已经显示过什么**（`liveSeen` 映射），不能来自节点里有什么；`forgetWorker` 要连 `liveSeen` 一起删，否则一个结束后又被派出去的 worker 回来时没有"到达"。

### 3.5 一个必须记住的 CSS 坑：渐变的 `transition`

`.composer-box` 原来有 `transition: … background …`，而焦点态改成了渐变。**渐变没有中间值**，`background` 一起过渡会在图像底下把颜色淡成透明。修法是拆开：

```css
background-color: var(--board-2);          /* 可过渡 */
transition: border-color .12s ease;         /* 只过渡边框 */
…
.composer-box:focus-within { background-image: linear-gradient(...); }  /* 瞬时 */
```

`.docs h2` 的小节线同理用 `background-image` + `background-size/position/repeat` 画成一条 1px 的带子，而不是 `border-image`——`border-image` 一旦哪天加了别的边，会四条边一起被替换掉。

### 3.6 一个开关

```css
@media (prefers-reduced-motion: reduce) { * { animation: none !important; transition: none !important; } }
```

**恰好一条**（中途出现过两条重复的，已合并，`grep -c` = 1）。`.just-captured` 这个类仍然会加上，只是不再动——操作员要求不动，结果还是结果。

实测（`Emulation.setEmulatedMedia`）：

| 媒体 | `just-captured` | `animationName` | 按钮 `transitionDuration` |
|---|---|---|---|
| `reduce` | 仍然加上 | `none` | `0s` |
| `no-preference` | 加上 | `sheet-settle` | `0.12s, 0.12s, 0.12s` |

## 6. 教训（下次直接用）

- **"动画不播"先查节点还在不在**。服务端渲染 + 定时整块刷新，是这个项目里最常见的一类"标记加了但看不见"：类是对的、选择器是对的、动画是定义了的，只是加在了一个几百毫秒后就被 `innerHTML` 丢掉的东西上。挂一个 MutationObserver 看 `childList`，比逐个排除快得多。
- **渐变不能用 `background` 过渡**。要过渡就把 `background-color` 和 `background-image` 拆开，且通常正确的做法是"焦点态本来就不该渐变过渡"。
- **深底上"往下落"的渐变几乎总是安全的**（只会抬高上面的对比度），"往上提亮"才需要算。侧栏和键帽是两个方向的例子。
- **凹陷物（输入井）的方向要和凸起物相反**，否则它读起来是个按钮。
- **表露"新"的动画必须由"刚刚发生"驱动，不能由"它存在"驱动**。服务端渲染的页面里，这两件事不是一回事。
